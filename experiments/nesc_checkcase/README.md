# NASA NESC 6DOF 검증 사례 — 독립 기준 대조 (비생산)

ADR-0003 §4-2 ①. **생산 코드가 아니며** `COLCON_IGNORE`로 빌드에서 제외돼
있다. 승인 범위: 비생산 래퍼 · 검증 사례 입력 · 기준 시계열 비교 ·
ECEF/ENU 및 상태 추출 검증 · 고정 스텝 결정성·비용 재측정. **그 이상은
승인되지 않았다** — 프로젝트 정의 형상 동결, 자세전환 제어기, 후보 탐색,
플래너 연결, 생산 빌드 의존성은 전부 보류.

## 왜 이것이 먼저인가

공력 계수를 논하기 전에 **6DOF 방정식·좌표계·환경 모델 구현이 맞는지**
독립 기준으로 증명해야 한다. 우리 모델의 계수가 옳은지와, 우리 적분기가
옳은지는 다른 질문이다. 후자는 공개 기준으로 지금 답할 수 있다.

## 자료

- **NASA/TM-2015-218675 (NESC-RP-12-00770) Vol. I·II**, 2015년 1월
- NESC Academy Flight Mechanics 영역에서 공개 배포
- 대기권 17건 + 궤도 26건. 비행체·초기조건·모델 상세·기준 시계열 제공
- 모델 표기는 AIAA/ANSI S-119-2011 (DAVE-ML XML)

`./fetch.sh`가 보고서·사양 페이지·대기권 사례 페이지를 `.nesc/`로 받는다
(gitignore, 커밋하지 않음).

## 중요한 성질 — "정답 하나"가 아니다

보고서가 스스로 밝힌다:

> Instead of identifying a single "known good" simulation tool, or requiring
> all trajectories match within a predefined tolerance, the approach taken
> was to present comparison plots … the set of trajectories would serve as a
> **family of possible solutions**.

즉 이 자료는 **해답의 족(族)**이지 단일 진리가 아니다. 적분법·중력 모델·
측지 모델 차이로 도구 간 차이가 실제로 관측됐다. 따라서 대조의 목적은
"일치 증명"이 아니라 **우리 결과가 그 족 안에 드는가, 벗어나면 어느 모델
선택 때문인가**를 밝히는 것이다.

부수 사실: **JSBSim이 이 비교에 참여한 도구 중 하나였다**(팀 명단에 JSBSim
프로젝트 포함). 우리가 JSBSim을 쓰면 대조는 "같은 도구가 같은 답을 내는가"에
가까워지므로, **적분기 검증으로서의 독립성이 그만큼 약하다.** 이 한계를
결과에 표기해야 한다.

## 우리에게 맞는 사례

| 사례 | 내용 | 왜 |
|---|---|---|
| **acc02** | 회전 직육면체, 무항력 | **감쇠 없는 강체 회전만 격리.** 공력 데이터 없이 자세 전파를 검사 |
| **acc03** | 회전 직육면체 + 공력 감쇠 | **공력 감쇠 계수를 명시적으로 쓴다.** acc02와 달리 공력이 없는 사례가 아니다 |
| **acc01 / acc04–06** | 낙하 구체 (무항력 / 비회전 구형 / 회전 구형 / 회전 타원체) | 중력·측지·좌표계·적분 |
| acc07 / acc08 | 낙하 구체 + 정상·변동 바람장 | 바람 모델 (현 범위 밖, 참고) |
| acc09 / acc10 | 구체 자유 비행 (동·북 방향) | 회전 지구 효과 |
| acc11–17 | 유인기 모델 (비선형 공력·추진·제어 법칙) | 명명이 제한 도메인. 필요 시 번호로만 참조 |

**acc02가 최우선**이다. 우리가 3DOF에서 못 하는 것이 정확히 자세이고,
acc02는 공력 데이터 없이 회전 동역학만 격리한다. **acc03은 다르다** —
사양이 공력 감쇠 계수를 명시적으로 요구하므로 "공력 없는 사례"가 아니다.
순서는 acc02로 자세 전파를 먼저 고정하고, acc03에서 감쇠 모멘트만 더한다.

**앞선 판(2026-08-15 초판)이 "정적 URL이 없다"고 적은 것은 틀렸다.** 경로는
사이트의 매니페스트 `/workshop/FlightSim/js/2015/dates.js` 에 공개돼 있고,
`fetch.sh`가 거기서 뽑아 받는다.

```
매니페스트  /workshop/FlightSim/js/2015/dates.js
CSV 기준    /workshop/FlightSim/2015/atmos_scn_{02,03}/Atmos_{02,03}_sim_{01,02,04,05,06}.csv
```

acc02·acc03 각 **5개, 합 10개** 확보. `fetch.sh`는 fail-closed다:

- 매니페스트에서 사례당 경로가 정확히 5개가 아니면 중단
- 파일이 1000 바이트 미만이면 중단
- 자세 전파 검증에 필요한 열이 없으면 중단
- 합계가 10개가 아니면 중단

URL과 SHA-256은 `.nesc/manifest.txt`에 남기고, **원시 CSV는 커밋하지
않는다**(`.gitignore`).

### 비교기가 다뤄야 하는 실측 사실

| 사실 | 영향 |
|---|---|
| 참여 도구 5종의 **열 구성이 다르다** (27~38열) | 공통은 **25열**. 위치는 지구고정 직교좌표가 아니라 **고도·위경도로만** 공통 |
| 출력 주기가 다르다 — **301 표본**(4종) / **3001 표본**(1종) | 아래 참조. 재표본은 **필요 없다** |

공통 25열에 오일러각 3개와 몸체 각속도 3개가 모두 들어 있으므로 **자세
전파 검증에는 충분하다.**

앞선 판이 302 / 3002라 적은 것은 **CSV 줄 수**이며 헤더가 포함된 값이었다.
표본은 301 / 3001이다.

**재표본은 필요 없다.** 열 파일 모두 0–30 s 를 0.1 s 로 덮는 **301점 공통
격자**를 갖는다(고주기 파일도 같은 격자를 포함). 실측한 최근접 시각 오차는
최대 **7.629e-7 s** 이므로 최근접 표본을 **1e-6 s 이내에서만 수용**하면
된다. 오일러각을 보간하면 래핑·특이점에서 조용히 틀리므로, 보간하지 않는
편이 안전하고 이 자료에서는 보간할 이유도 없다.

### 합격선을 만들지 않는다

참여 결과의 최솟값–최댓값 안에 드는 것을 **합격 조건으로 삼지 않는다.**
보고서 자체가 단일 정답을 거부하고 해의 족을 제시한다. 우리가 보고할 것은
**각 참여 결과와의 차이, 그리고 족의 산포**이며, 둘 다 판정이 아니라
측정값이다.

## 비교 방법 — 오일러각을 직접 빼지 않는다

±180° 경계에서 1° 차이가 359°로 보이고, 피치 ±90° 근처에서는 롤·요가 겹쳐
같은 자세가 전혀 다른 각으로 표기된다. 그래서:

```
오일러각 → 쿼터니언   (NESC 규약: NED 기준, 3-2-1 = yaw→pitch→roll)
자세 차이 = 2 · acos(|q1 · q2|)        (q 와 −q 가 같은 자세이므로 절댓값)
```

이 각거리는 표기법에 무관한 실제 회전 각이다.

각속도는 공식 출력 사양상 **지구 관성계에 대한 몸체 각속도를 몸체축으로**
표현한 deg/s 값이고 다섯 파일이 같은 정의를 쓰므로, 단위·프레임을 맞춘 뒤
성분별로 비교한다.

`compare_acc02.py --scenario {02,03}` 이 이를 수행한다.

## 측정된 족의 산포 (2026-08-15)

**합격선이 아니라 측정값이다.** 우리 구현을 넣기 전에 족 자체가 얼마나
퍼져 있는지 알아야, 나중에 우리 결과의 차이를 해석할 수 있다.

| | acc02 (무항력) | acc03 (공력 감쇠) |
|---|---|---|
| 자세 각거리, 쌍별 최대의 최댓값 | **3.7135°** | **0.6610°** |
| 몸체 각속도 최대 차이 (Roll/Pitch/Yaw) | 0.0030 / 0.0047 / 0.0012 °/s | 더 큼 (0.03~0.07 급) |

acc02에서 눈에 띄는 구조가 있다:

- sim 01·04·05가 **0.0001° 수준으로 일치**
- sim 06이 0.0104°
- **sim 02만 3.71° 벌어진다** — 그런데 **각속도는 0.001 °/s 수준으로 일치**한다

각속도 차이 0.001 °/s를 30초 적분해도 0.03°이지 3.7°가 되지 않는다. 즉
sim 02의 차이는 각속도 오차 누적이 아니라 **자세 표현·적분 또는 초기조건
해석의 구조적 차이**로 보인다. 이 관찰 자체가 이 비교의 산출물이며, 원인
규명은 아직 하지 않았다.

acc03에서는 감쇠가 들어가면서 족이 반대로 **자세는 좁아지고(0.66°) 각속도는
넓어진다.** 감쇠 모델 구현 차이가 각속도에 직접 나타나는 것으로 읽히나,
이 역시 관찰이며 규명은 하지 않았다.

## 결정성·비용 재측정 (2026-08-15)

기존 프로브(`../jsbsim_probe`, JSBSim v1.3.1 고정)로 다시 측정했다.

| 항목 | 값 |
|---|---|
| 동일 입력 2회, **관측한 종단 스칼라 2개** | `end \|v\| = 132.29`, `end z = 691.42 m` — 동일 |
| 동일 입력 2회, **stdout 전체** | **불일치** |
| 스텝당 비용 | 8.0–8.3 µs/step (dt 0.001에서 12000 스텝) |
| 27 프로파일 × 30 s | 695 ms, 15개가 부분 인계창 유지 |

**여기서 말할 수 있는 것은 딱 이만큼이다.** 프로브가 실제로 비교하는 것은
두 번 실행한 뒤의 `end z` 와 `end |v|` **두 값뿐**이다. 앞선 판이 *"물리 열은
동일하다"*고 쓴 것은 측정 범위를 넘는 서술이었다.

**"물리 열 전체 비트 일치"를 주장하려면** 시간축 전체에 걸쳐 위치·속도·
자세·각속도·질량을 표본별로 비교하고, 실행시간 열(`wall[ms]`, `us/step`)만
제외해야 한다. 아직 하지 않았다.

stdout이 불일치하는 이유는 물리가 아니다 — 출력 표에 `wall[ms]`와
`us/step`이 섞여 있어 실행마다 달라진다(97.5 vs 96.6 ms). 결정성 게이트를
만들 때 stdout 전체를 비교하면 타이밍 잡음으로 반드시 실패한다.

기존 기록(~10 µs/step, 866 ms)과 이번 측정(8.0–8.3 µs/step, 695 ms)의 차이는
장비 부하 수준이며 결론을 바꾸지 않는다.
