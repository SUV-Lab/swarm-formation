# NASA NESC 6DOF 검증 사례 — 독립 기준 대조 (비생산)

ADR-0003 §4-2 ①. **생산 코드가 아니며** `COLCON_IGNORE`로 빌드에서 제외돼
있다. 승인 범위: 비생산 래퍼 · 검증 사례 입력 · 기준 시계열 비교 ·
ECEF/ENU 및 상태 추출 검증 · 고정 스텝 결정성·비용 재측정. **그 이상은
승인되지 않았다** — 프로젝트 정의 형상 동결, 자세전환 제어기, 후보 탐색,
플래너 연결, 생산 빌드 의존성은 전부 보류.

## 왜 이것이 먼저인가

공력 계수를 논하기 전에 **6DOF 방정식·좌표계·환경 모델 구현이 맞는지**
독립 기준으로 증명해야 한다. 우리 모델의 계수가 옳은지와, 우리 적분기가
옳은지는 다른 질문이다. 후자는 공개 기준으로 지금 답할 수 있다.

## 중요한 성질 — "정답 하나"가 아니다

보고서가 스스로 밝힌다:

> Instead of identifying a single "known good" simulation tool, or requiring
> all trajectories match within a predefined tolerance, the approach taken
> was to present comparison plots … the set of trajectories would serve as a
> **family of possible solutions**.

즉 이 자료는 **해답의 족(族)**이지 단일 진리가 아니다. 적분법·중력 모델·
측지 모델 차이로 도구 간 차이가 실제로 관측됐다. 따라서 대조의 목적은
"일치 증명"이 아니라 **우리 결과가 그 족 안에 드는가, 벗어나면 어느 모델
선택 때문인가**를 밝히는 것이다.

부수 사실: **JSBSim이 이 비교에 참여한 도구 중 하나였다**(팀 명단에 JSBSim
프로젝트 포함). 우리가 JSBSim을 쓰면 대조는 "같은 도구가 같은 답을 내는가"에
가까워지므로, **적분기 검증으로서의 독립성이 그만큼 약하다.** 이 한계를
결과에 표기해야 한다.

## 비교 방법 — 오일러각을 직접 빼지 않는다

±180° 경계에서 1° 차이가 359°로 보이고, 피치 ±90° 근처에서는 롤·요가 겹쳐
같은 자세가 전혀 다른 각으로 표기된다. 그래서:

```
오일러각 → 쿼터니언   (NESC 규약: NED 기준, 3-2-1 = yaw→pitch→roll)
자세 차이 = 2 · acos(|q1 · q2|)        (q 와 −q 가 같은 자세이므로 절댓값)
```

이 각거리는 표기법에 무관한 실제 회전 각이다.

각속도는 공식 출력 사양상 **지구 관성계에 대한 몸체 각속도를 몸체축으로**
표현한 deg/s 값이고 다섯 파일이 같은 정의를 쓰므로, 단위·프레임을 맞춘 뒤
성분별로 비교한다.

`compare_attitude_family.py --scenario {02,03}` 이 이를 수행한다.
이름이 `compare_acc02.py` 였으나 acc03도 처리하므로 범위에 맞게 바꿨다.

### 불변량이 참여 결과 없이 같은 결론에 도달한다

acc02는 감쇠 없는 강체이고 중력만 작용하므로 CM 둘레 외부 모멘트가 0이다.
따라서 **회전 운동에너지**와 **관성계 각운동량 벡터**가 보존된다. 이것은
참여 결과의 산포에서 만든 합격선이 아니라 **해석적 불변량**이므로 비교기
자신에 대한 자기검사가 된다. 관성은 부록 표 4(벽돌, CM 기준, 곱관성 0).

관성은 부록 표 4(벽돌, CM 기준, 곱관성 0). **프레임은 ECI다:**

```
H_body = I · ω_body
H_ned  = R_ned_body(q) · H_body
H_ecef = R_ecef_ned(위도, 경도) · H_ned
H_eci  = Rz(ω_지구 · t) · H_ecef        ω_지구 = 7.292115e-5 rad/s (WGS-84)
```

| sim | KE 상대변동 | ‖H‖ 상대변동 | **H_eci 방향 드리프트** |
|---|---|---|---|
| 01 | 4.16e-12 | 2.03e-12 | 0.0000012° |
| **02** | **7.12e-06** | **3.37e-06** | **3.7128827°** |
| 04 | 7.56e-12 | 3.76e-12 | 0.0000015° |
| 05 | 2.83e-07 | 1.34e-07 | 0.0000240° |
| 06 | 1.98e-09 | 7.61e-10 | 0.0038102° |

**크기만 보면 놓친다.** 몸체축 각속도가 맞고 자세만 틀리면 ‖H‖는 거의
유지되면서 방향이 돈다. 방향 드리프트 **3.713°**는 쌍별 자세 각거리
3.7135°와 사실상 같은 값이며, **다른 도구를 한 번도 보지 않고** sim 02를
지목한다.

### 정정 — 앞선 판의 "0.125° 불변량 바닥"은 틀렸다

앞선 판은 `H_ned`를 관성계 각운동량이라 부르고, 좋은 결과 넷의 공통
0.125°를 수치 바닥이라 적었다. **NED는 지구와 함께 돈다.** 그 0.125°는
바닥이 아니라 **30초치 지구 자전각**이었다:

```
7.292115e-5 rad/s × 30 s = 2.1876e-3 rad = 0.1253°
```

즉 그 검사는 각운동량 보존이 아니라 지구 자전을 재고 있었다. ECEF→ECI
변환을 넣자 좋은 결과들이 **1e-6 ~ 4e-3° 수준**으로 내려가고, sim 02만
3.713°로 남는다. **결론은 유지되고 오히려 깨끗해진다.**

이 실수가 다시 들어오지 못하도록 회귀를 걸었다:

> 지구 자전 변환을 제거하면 sim 01·04·05의 방향 드리프트가 30초 자전각
> (0.1253°)으로 **악화돼야 한다.** 악화되지 않으면 변환이 실제로 적용되지
> 않은 것이므로 종료코드 3.

측정: 제거 시 0.1250° — 자전각과 0.01° 이내로 일치.

초기 GAST의 상수 오프셋은 한 실행 안의 방향 드리프트만 볼 때 상쇄된다
(모든 표본에 같은 회전이 곱해진다). 서로 다른 절대 방향을 직접 비교할
때에만 공통 시각 기준이 추가로 필요하다.

## 1e-6° 는 "바닥"이 아니다

앞선 판이 이를 불변량 바닥처럼 읽었다. **해석적 바닥도 아니고 후보
합격선도 아니다.** 참여 결과 01·04에서 **관측된 작은 잔차**일 뿐이며,
다른 도구·다른 적분법에서는 다른 값이 나온다. 우리 후보를 이 값에
맞추라는 요구로 쓰지 않는다.

## 후보 생성 전 — t=0 초기조건 계약

`ic_contract.py`. **각속도 프레임이 둘이라** 따로 뒀다.

JSBSim: `vPQRi = vPQR + Ti2b * omegaPlanet`

| | 기준 | 값 |
|---|---|---|
| `pi/qi/ri` | **관성계** | **10 / 20 / 30** °/s |
| `p/q/r` | ECEF (회전하는 지구) | **9.9958219259** / 20 / 30 °/s |

**NESC 출력의 10/20/30 은 관성계 값이다.** 사양 본문이 못 박는다 —
*"the inertial rates were 10, 20 and 30 deg/s … Table 26 gives these rates
relative to the rotating Earth, so a smaller value for 'roll rate' is
specified."*

따라서 JSBSim 의 일반 `p/q/r` 에 10/20/30 을 그대로 넣으면 **지구 자전분이
한 번 더 붙는다.** 적도·본초자오선·자세 0/0/0 에서는 NED 기저의 지구 자전
벡터가 북(roll)축 성분만 가지므로:

```
ω_지구 = 7.292115e-5 rad/s = 0.0041780741 °/s
p_ecef = 10 − 0.0041780741 = 9.9958219259 °/s     (q, r 은 불변)
```

`attitude_rate frame="eci"` 를 쓰면 입력이 몸체 PQR 이 아니라 ECI 성분이라
좌표변환이 또 필요하다. **어떤 입력 방법을 쓰든 초기화 직후 결과를 직접
단정**하는 것이 안전하고, 그것이 이 파일이 하는 일이다.

핀 대상: `pqri` · `pqr` · 자세 0/0/0 · 위경도 0 · 고도 30,000 ft ·
local velocity 0. 후보 CSV 에는 **`GetPQRi()`** 를 기록한다.

변이 4종 전부 죽는다 `[재현: ic_contract.py --selftest]`:

| 변이 | |
|---|---|
| 프레임 구분 제거 (`PQR = PQRi`) | 죽음 |
| 자전 보정 부호 반대 | 죽음 |
| 관성계 값 변조 | 죽음 |
| 각속도 허용오차 무력화 | 죽음 |

상수를 **리터럴로도** 단정한다. 픽스처를 상수에서만 만들면 상수를 바꾸는
변이가 픽스처도 함께 바꿔 살아남는다 — 첫 판이 그랬다.

## 비교기 자신의 검증

`--selftest` 가 **나쁜 입력**으로 계약 검사를 시험한다. 정상 자료만으로는
임계값을 고정할 수 없다 — 시각 허용오차를 무한대로 풀어도 좋은 자료는
여전히 통과하므로 검사가 살아 있는지 알 수 없다.

변이로 확인한 결과:

| 조항 | 무력화 시 |
|---|---|
| 대응 오차 ≤ 1e-6 s | **죽음** |
| 원본 엄격 증가 | **죽음** |
| 표본 유한성 | **죽음** |
| 쿼터니언 정규화 | **죽음** |
| 중복 시각 | 살아남음 — **포섭됨** |
| 격자 일대일 | 살아남음 — **포섭됨** |

뒤 둘은 논리적으로 앞 조항에 포섭된다:

```
엄격 증가                       ⟹ 중복 없음
엄격 증가 + 격자간격 0.1 ≫ 2e-6 ⟹ 격자점마다 최근접이 유일
```

그래서 그 조항만 위반하는 입력을 만들 수 없다. 방어를 위해 남기되
**독립 고정은 불가능**하며, 살아남는 변이를 "검사가 약하다"로 오해하지
않도록 여기 적어둔다.

첫 판의 계약 검사는 **동어반복**이었다 — `load()` 가 이미 골라낸 301개를
다시 301개인지 세고, 그 301개의 시각만 보았다. 구성상 항상 참이다. 이제
원본 CSV 전체를 본다.

## 지구 자전 회귀는 양팔이다

한쪽만 보면 통과한다. `earth_rotation=False` 결과가 0.125°인지만 검사하면,
**정상 경로에서 ECI 변환을 삭제해도** false 팔은 원래 자전을 빼지 않으므로
그대로 0.125°가 나와 회귀가 통과한다.

그래서 세 가지를 함께 단정한다:

| | 요구 | 측정 |
|---|---|---|
| 보정 ON (sim 01·04·05) | < 0.001° | 0.0000240° |
| 보정 OFF | 자전각 0.1253° ± 0.01° | 0.1250° |
| 개선 비율 | ≥ 100배 | **5199배** |

변이 확인: 정상 경로의 `ecef_to_eci()` 호출을 지우면 ON이 0.1250°가 되고
개선 비율이 1배로 떨어져 **종료코드 3**.

## 결정성·비용 재측정 (2026-08-15)

기존 프로브(`../jsbsim_probe`, JSBSim v1.3.1 고정)로 다시 측정했다.

| 항목 | 값 |
|---|---|
| 동일 입력 2회, **관측한 종단 스칼라 2개** | `end \|v\| = 132.29`, `end z = 691.42 m` — 동일 |
| 동일 입력 2회, **stdout 전체** | **불일치** |
| 스텝당 비용 | 8.0–8.3 µs/step (dt 0.001에서 12000 스텝) |
| 27 프로파일 × 30 s | 695 ms, 15개가 부분 인계창 유지 |

**여기서 말할 수 있는 것은 딱 이만큼이다.** 프로브가 실제로 비교하는 것은
두 번 실행한 뒤의 `end z` 와 `end |v|` **두 값뿐**이다. 앞선 판이 *"물리 열은
동일하다"*고 쓴 것은 측정 범위를 넘는 서술이었다.

**"물리 열 전체 비트 일치"를 주장하려면** 시간축 전체에 걸쳐 위치·속도·
자세·각속도·질량을 표본별로 비교하고, 실행시간 열(`wall[ms]`, `us/step`)만
제외해야 한다. 아직 하지 않았다.

stdout이 불일치하는 이유는 물리가 아니다 — 출력 표에 `wall[ms]`와
`us/step`이 섞여 있어 실행마다 달라진다(97.5 vs 96.6 ms). 결정성 게이트를
만들 때 stdout 전체를 비교하면 타이밍 잡음으로 반드시 실패한다.

기존 기록(~10 µs/step, 866 ms)과 이번 측정(8.0–8.3 µs/step, 695 ms)의 차이는
장비 부하 수준이며 결론을 바꾸지 않는다.
