# NASA NESC 6DOF 검증 사례 — 독립 기준 대조 (비생산)

ADR-0003 §4-2 ①. **생산 코드가 아니며** `COLCON_IGNORE`로 빌드에서 제외돼
있다. 승인 범위: 비생산 래퍼 · 검증 사례 입력 · 기준 시계열 비교 ·
ECEF/ENU 및 상태 추출 검증 · 고정 스텝 결정성·비용 재측정. **그 이상은
승인되지 않았다** — 프로젝트 정의 형상 동결, 자세전환 제어기, 후보 탐색,
플래너 연결, 생산 빌드 의존성은 전부 보류.

## 왜 이것이 먼저인가

공력 계수를 논하기 전에 **6DOF 방정식·좌표계·환경 모델 구현이 맞는지**
독립 기준으로 증명해야 한다. 우리 모델의 계수가 옳은지와, 우리 적분기가
옳은지는 다른 질문이다. 후자는 공개 기준으로 지금 답할 수 있다.

## 중요한 성질 — "정답 하나"가 아니다

보고서가 스스로 밝힌다:

> Instead of identifying a single "known good" simulation tool, or requiring
> all trajectories match within a predefined tolerance, the approach taken
> was to present comparison plots … the set of trajectories would serve as a
> **family of possible solutions**.

즉 이 자료는 **해답의 족(族)**이지 단일 진리가 아니다. 적분법·중력 모델·
측지 모델 차이로 도구 간 차이가 실제로 관측됐다. 따라서 대조의 목적은
"일치 증명"이 아니라 **우리 결과가 그 족 안에 드는가, 벗어나면 어느 모델
선택 때문인가**를 밝히는 것이다.

부수 사실: **JSBSim이 이 비교에 참여한 도구 중 하나였다**(팀 명단에 JSBSim
프로젝트 포함). 우리가 JSBSim을 쓰면 대조는 "같은 도구가 같은 답을 내는가"에
가까워지므로, **적분기 검증으로서의 독립성이 그만큼 약하다.** 이 한계를
결과에 표기해야 한다.

## 비교 방법 — 오일러각을 직접 빼지 않는다

±180° 경계에서 1° 차이가 359°로 보이고, 피치 ±90° 근처에서는 롤·요가 겹쳐
같은 자세가 전혀 다른 각으로 표기된다. 그래서:

```
오일러각 → 쿼터니언   (NESC 규약: NED 기준, 3-2-1 = yaw→pitch→roll)
자세 차이 = 2 · acos(|q1 · q2|)        (q 와 −q 가 같은 자세이므로 절댓값)
```

이 각거리는 표기법에 무관한 실제 회전 각이다.

각속도는 공식 출력 사양상 **지구 관성계에 대한 몸체 각속도를 몸체축으로**
표현한 deg/s 값이고 다섯 파일이 같은 정의를 쓰므로, 단위·프레임을 맞춘 뒤
성분별로 비교한다.

`compare_attitude_family.py --scenario {02,03}` 이 이를 수행한다.
이름이 `compare_acc02.py` 였으나 acc03도 처리하므로 범위에 맞게 바꿨다.

### 불변량이 참여 결과 없이 같은 결론에 도달한다

acc02는 감쇠 없는 강체이고 중력만 작용하므로 CM 둘레 외부 모멘트가 0이다.
따라서 **회전 운동에너지**와 **관성계 각운동량 벡터**가 보존된다. 이것은
참여 결과의 산포에서 만든 합격선이 아니라 **해석적 불변량**이므로 비교기
자신에 대한 자기검사가 된다. 관성은 부록 표 4(벽돌, CM 기준, 곱관성 0).

관성은 부록 표 4(벽돌, CM 기준, 곱관성 0). **프레임은 ECI다:**

```
H_body = I · ω_body
H_ned  = R_ned_body(q) · H_body
H_ecef = R_ecef_ned(위도, 경도) · H_ned
H_eci  = Rz(ω_지구 · t) · H_ecef        ω_지구 = 7.292115e-5 rad/s (WGS-84)
```

| sim | KE 상대변동 | ‖H‖ 상대변동 | **H_eci 방향 드리프트** |
|---|---|---|---|
| 01 | 4.16e-12 | 2.03e-12 | 0.0000012° |
| **02** | **7.12e-06** | **3.37e-06** | **3.7128827°** |
| 04 | 7.56e-12 | 3.76e-12 | 0.0000015° |
| 05 | 2.83e-07 | 1.34e-07 | 0.0000240° |
| 06 | 1.98e-09 | 7.61e-10 | 0.0038102° |

**크기만 보면 놓친다.** 몸체축 각속도가 맞고 자세만 틀리면 ‖H‖는 거의
유지되면서 방향이 돈다. 방향 드리프트 **3.713°**는 쌍별 자세 각거리
3.7135°와 사실상 같은 값이며, **다른 도구를 한 번도 보지 않고** sim 02를
지목한다.

### 정정 — 앞선 판의 "0.125° 불변량 바닥"은 틀렸다

앞선 판은 `H_ned`를 관성계 각운동량이라 부르고, 좋은 결과 넷의 공통
0.125°를 수치 바닥이라 적었다. **NED는 지구와 함께 돈다.** 그 0.125°는
바닥이 아니라 **30초치 지구 자전각**이었다:

```
7.292115e-5 rad/s × 30 s = 2.1876e-3 rad = 0.1253°
```

즉 그 검사는 각운동량 보존이 아니라 지구 자전을 재고 있었다. ECEF→ECI
변환을 넣자 좋은 결과들이 **1e-6 ~ 4e-3° 수준**으로 내려가고, sim 02만
3.713°로 남는다. **결론은 유지되고 오히려 깨끗해진다.**

이 실수가 다시 들어오지 못하도록 회귀를 걸었다:

> 지구 자전 변환을 제거하면 sim 01·04·05의 방향 드리프트가 30초 자전각
> (0.1253°)으로 **악화돼야 한다.** 악화되지 않으면 변환이 실제로 적용되지
> 않은 것이므로 종료코드 3.

측정: 제거 시 0.1250° — 자전각과 0.01° 이내로 일치.

초기 GAST의 상수 오프셋은 한 실행 안의 방향 드리프트만 볼 때 상쇄된다
(모든 표본에 같은 회전이 곱해진다). 서로 다른 절대 방향을 직접 비교할
때에만 공통 시각 기준이 추가로 필요하다.

## 1e-6° 는 "바닥"이 아니다

앞선 판이 이를 불변량 바닥처럼 읽었다. **해석적 바닥도 아니고 후보
합격선도 아니다.** 참여 결과 01·04에서 **관측된 작은 잔차**일 뿐이며,
다른 도구·다른 적분법에서는 다른 값이 나온다. 우리 후보를 이 값에
맞추라는 요구로 쓰지 않는다.

## 후보 생성 전 — t=0 초기조건 계약

`ic_contract.py`. **각속도 프레임이 둘이라** 따로 뒀다.

JSBSim: `vPQRi = vPQR + Ti2b * omegaPlanet`

| | 기준 | 값 |
|---|---|---|
| `pi/qi/ri` | **관성계** | **10 / 20 / 30** °/s |
| `p/q/r` | ECEF (회전하는 지구) | **9.9958219259** / 20 / 30 °/s |

**NESC 출력의 10/20/30 은 관성계 값이다.** 사양 본문이 못 박는다 —
*"the inertial rates were 10, 20 and 30 deg/s … Table 26 gives these rates
relative to the rotating Earth, so a smaller value for 'roll rate' is
specified."*

따라서 JSBSim 의 일반 `p/q/r` 에 10/20/30 을 그대로 넣으면 **지구 자전분이
한 번 더 붙는다.** 적도·본초자오선·자세 0/0/0 에서는 NED 기저의 지구 자전
벡터가 북(roll)축 성분만 가지므로:

```
ω_지구 = 7.292115e-5 rad/s = 0.0041780741 °/s
p_ecef = 10 − 0.0041780741 = 9.9958219259 °/s     (q, r 은 불변)
```

`attitude_rate frame="eci"` 를 쓰면 입력이 몸체 PQR 이 아니라 ECI 성분이라
좌표변환이 또 필요하다. **어떤 입력 방법을 쓰든 초기화 직후 결과를 직접
단정**하는 것이 안전하고, 그것이 이 파일이 하는 일이다.

핀 대상: `pqri` · `pqr` · 자세 0/0/0 · 위경도 0 · 고도 30,000 ft ·
local velocity 0. 후보 CSV 에는 **`GetPQRi()`** 를 기록한다.

변이 4종 전부 죽는다 `[재현: ic_contract.py --selftest]`:

| 변이 | |
|---|---|
| 프레임 구분 제거 (`PQR = PQRi`) | 죽음 |

## 비교기 자신의 검증

`--selftest` 가 **나쁜 입력**으로 계약 검사를 시험한다. 정상 자료만으로는
임계값을 고정할 수 없다 — 시각 허용오차를 무한대로 풀어도 좋은 자료는
여전히 통과하므로 검사가 살아 있는지 알 수 없다.

변이로 확인한 결과:

| 조항 | 무력화 시 |
|---|---|
| 대응 오차 ≤ 1e-6 s | **죽음** |
| 원본 엄격 증가 | **죽음** |
| 표본 유한성 | **죽음** |
| 쿼터니언 정규화 | **죽음** |
| 중복 시각 | 살아남음 — **포섭됨** |
| 격자 일대일 | 살아남음 — **포섭됨** |

뒤 둘은 논리적으로 앞 조항에 포섭된다:

```
엄격 증가                       ⟹ 중복 없음
엄격 증가 + 격자간격 0.1 ≫ 2e-6 ⟹ 격자점마다 최근접이 유일
```

그래서 그 조항만 위반하는 입력을 만들 수 없다. 방어를 위해 남기되
**독립 고정은 불가능**하며, 살아남는 변이를 "검사가 약하다"로 오해하지
않도록 여기 적어둔다.

첫 판의 계약 검사는 **동어반복**이었다 — `load()` 가 이미 골라낸 301개를
다시 301개인지 세고, 그 301개의 시각만 보았다. 구성상 항상 참이다. 이제
원본 CSV 전체를 본다.

## 결정성·비용 재측정 (2026-08-15)

기존 프로브(`../jsbsim_probe`, JSBSim v1.3.1 고정)로 다시 측정했다.

| 항목 | 값 |
|---|---|
| 동일 입력 2회, **관측한 종단 스칼라 2개** | `end \|v\| = 132.29`, `end z = 691.42 m` — 동일 |
| 동일 입력 2회, **stdout 전체** | **불일치** |
| 스텝당 비용 | 8.0–8.3 µs/step (dt 0.001에서 12000 스텝) |
| 27 프로파일 × 30 s | 695 ms, 15개가 부분 인계창 유지 |

**여기서 말할 수 있는 것은 딱 이만큼이다.** 프로브가 실제로 비교하는 것은
두 번 실행한 뒤의 `end z` 와 `end |v|` **두 값뿐**이다. 앞선 판이 *"물리 열은
동일하다"*고 쓴 것은 측정 범위를 넘는 서술이었다.

**"물리 열 전체 비트 일치"를 주장하려면** 시간축 전체에 걸쳐 위치·속도·
자세·각속도·질량을 표본별로 비교하고, 실행시간 열(`wall[ms]`, `us/step`)만
제외해야 한다. 아직 하지 않았다.

stdout이 불일치하는 이유는 물리가 아니다 — 출력 표에 `wall[ms]`와
`us/step`이 섞여 있어 실행마다 달라진다(97.5 vs 96.6 ms). 결정성 게이트를
만들 때 stdout 전체를 비교하면 타이밍 잡음으로 반드시 실패한다.

기존 기록(~10 µs/step, 866 ms)과 이번 측정(8.0–8.3 µs/step, 695 ms)의 차이는
장비 부하 수준이며 결론을 바꾸지 않는다.

### 스텝 수렴 — 깨끗한 1차

| dt | 자세 차이(01 대비) | KE 잔차 | H 방향 드리프트 | 개선 |
|---|---|---|---|---|
| 0.01 | 2.6132° | 9.319e-03 | 0.1495° | — |

| 0.0001 | 0.0258° | 9.171e-05 | 0.0015° | **10.0배** |

dt 를 10배 줄일 때마다 세 지표가 모두 정확히 10배 개선된다. 이는
**시험한 범위에서 1차 시간 이산화 오차가 지배한다**는 뜻이다. 모델 차이가

```
E(h) = C·h + E_model
```

C·h 가 커서 E_model 이 가려져 있을 수 있다.

주목할 점: 우리 후보의 불변량 잔차(dt 0.001 에서 KE 9.2e-04)는 **참여

더 정교한 적분법을 쓰거나 더 작은 내부 스텝을 쓴다는 뜻이며, 우리 쪽
적분 설정이 아직 그 수준이 아니라는 **측정된 사실**이다. dt 1e-4 에서도
9.2e-05 로 여전히 크다. 적분법 선택은 후속 과제다.

## 적분기 스윕 (2026-08-15)

### 왜 필요했나 — 문서와 구현이 다르다

JSBSim v1.3.1 은 생성자에서 회전 각속도와 회전 자세를 **둘 다
`eRectEuler`** 로 둔다:

```cpp
integrator_rotational_rate     = eRectEuler;      // FGPropagate.cpp:93
integrator_rotational_position = eRectEuler;      // FGPropagate.cpp:95
```

그런데 헤더 주석은 기본값을 다르게 적는다:

> integrator, rotational rate = Adams Bashforth 2
> integrator, rotational position = Trapezoidal
> — FGPropagate.h:143

**문서와 구현이 다르므로 기본값에 의존하면 안 된다.** 생성기는 값을
명시적으로 설정하고, 실행 시 읽어서 단정한다(불일치 시 종료코드 3).

### 결과 (dt = 0.001) — 안정 계산식으로 재측정

| 조합 | vs sim01 자세 | KE 잔차 | ‖H‖ 잔차 | H 방향 | 비용 |
|---|---|---|---|---|---|
| RectEuler / RectEuler | 2.586e-01° | 9.184e-04 | 3.776e-04 | 1.489e-02° | 0.048 s |
| AB2 / Buss2 | 2.171e-05° | 7.063e-08 | 3.349e-08 | 6.017e-06° | 0.048 s |
| **AB4 / Buss2** | **3.621e-06°** | **3.858e-09** | 1.476e-09 | 3.005e-06° | 0.050 s |
| AB5 / LocalLinearization | 7.985e-06° | 3.858e-09 | 1.476e-09 | **1.710e-06°** | 0.050 s |

앞선 판은 아래 셋을 전부 `0.0000°` 로 적어 **같아 보이게** 만들었다. 원인은
비교기가 작은 각에서 `acos(dot)` 을 쓴 것이다 — 측정하면 1e-6° 에서 상대오차
**14.6%** 다. `dot` 이 1 에 붙으면 `cos` 의 기울기가 0 이라 유효숫자가 날아간다.

고친 계산식:

```
자세      상대 쿼터니언 q_rel = conj(q1)·q2 → 2·atan2(‖vec‖, |w|)
벡터 방향  atan2(‖a×b‖, a·b)
```

**AB4/Buss2 와 AB5/LocalLinearization 은 같지 않다.** 전자는 자세 차이가
작고(3.6e-6 대 8.0e-6), 후자는 각운동량 방향 보존이 낫다(1.7e-6 대 3.0e-6).
`.hex` 파일도 서로 다르다.

### 고차 적분기의 초기 거동

JSBSim 은 멀티스텝 이력을 **초기 미분값으로 5칸 전부 채우고** 시작한다:

```cpp
VState.dqPQRidot.assign(5, in.vPQRidot);        // FGPropagate.cpp:190
```

그래서 고차 Adams–Bashforth 가 초기 몇 스텝에서 이점을 갖지 못한다.
최초 10스텝(dt 0.001)의 불변량 잔차:

| 조합 | KE 잔차 | H 방향 |

| AB4/Buss2 | 3.666e-08 | 1.974e-06° |

**최초 10스텝, 즉 0.01초의 KE 보존은 AB2 가 낫다.** 차수가 높을수록 채워진 가짜 이력에 더
오래 끌린다는 뜻으로 읽힌다. 다만 **0.01초 순위가 전체 구간 선택을

## acc03 (감쇠) 대조 — 재측정

**앞선 판은 철회한다.** 사례 구성이 틀렸다.

기준 brick 표(부록 표 5)는 CD 0.01 이지만, **사례 3 이 그 값을 0 으로
덮어쓴다.** 사례명 자체가 *"**Dragless** Brick with Aerodynamic Damping"*
이다. 첫 모델은 기준 표 값만 적용하고 사례별 덮어쓰기를 빠뜨려 항력을
실제로 걸었다.

항력은 낙하 속도 → 동압 → 감쇠 모멘트로 이어지므로 **자세 결과에 직접
영향**을 준다. 따라서 앞선 0.48~0.94° 를 "감쇠 구현 차이"로 읽은 것도,
"적분기가 구분되지 않는다"는 결론도 무효였다.

### 고친 계약

생성기는 이제 사례를 **명시적으로 분류**한다(`acc02` / `acc03`, 그 외 거부).
`model != "nesc_brick"` 같은 간접 분류는 오타 하나로 다른 계약을 조용히
적용한다.

acc03 계약:

| | |
|---|---|
| 공력 **힘** | 전 구간 **0** (사례가 CD 를 0 으로 덮어씀) |
| 공력 **모멘트** | 유의미하게 0 아님 |
| 축별 모멘트 | **해석식으로 재폐쇄** — `L = q̄·S·b·Clp·(p·b/2V)` 등 |

"0이 아니다"만 보면 계수나 축이 틀려도 통과한다. 매 스텝 세 축을 모두
재폐쇄하고, 1e-9 상대오차를 넘으면 종료코드 3.

|---|---|---|---|---|---|
| RectEuler | 3.225e-01 | 6.645e-01 | 1.055e-01 | 2.157e-02 | 2.326e-02 |

항력을 뺀 뒤 **sim 05·06 과 0.004~0.005° 로 일치**한다 — 잘못된 판의

적분기 구분: **RectEuler 는 구분된다** (sim05 대비 2.157e-02 로 AB2 의
5.7배). AB2·AB4·AB5 는 여전히 소수 세 자리까지 같아 acc03 이 이 셋을
가르지 못한다.

## 두 KE 지표는 다른 것을 잰다

시간창 표가 재는 것은 [0,T] 의 **누적 max−min** 이고, 순간 지표는
`|KE(t)−KE(0)|/KE(0)` 이다. 앞선 판은 후자를 보고 "AB4 가 전 구간
우세"라 적었는데, **누적 표와 충돌한다** — 누적은 0.01초 창에서 AB2
2.313e-08, AB4 3.666e-08 로 AB2 가 낫다고 말한다.

전 스텝으로 재니 둘 다 옳고 서로 다른 것을 재고 있었다:

| 조합 | 부호 최대(+) | 부호 최소(−) | max−min | **&#124;Δ&#124; 최대** |
|---|---|---|---|---|
| AB2/Buss2 | 2.313e-08 | 0.000e+00 | 2.313e-08 | 2.313e-08 |
| AB4/Buss2 | 2.313e-08 | −1.353e-08 | **3.666e-08** | 2.313e-08 |

**최대 편차는 둘이 같다** (2.313e-08, 첫 스텝 t=0.001). 차이는 AB4 가
**양쪽으로 진동**한다는 것뿐이고, 그래서 max−min 만 커진다.

정착이 갈린다:

| t [s] | AB2 | AB4 |
|---|---|---|
| 0.001 | 2.313e-08 | 2.313e-08 |
| 0.002 | 2.310e-08 | 1.353e-08 |
| 0.003 | 2.308e-08 | **3.871e-09** |
| 0.01 | 2.293e-08 | 3.854e-09 |
| 0.5 | 1.373e-08 | 3.855e-09 |
| 30 | 3.473e-08 | 3.852e-09 |

**AB4 는 3스텝 만에 3.85e-09 로 정착해 30초 내내 그대로**다. AB2 는
2.3e-08 에서 천천히 줄다가 다시 커진다.

따라서 정확한 서술은:

- **최초 excursion 최대값**: 둘이 동일 (2.313e-08 @ t=0.001)
- **누적 max−min 0.01초 창**: AB2 우세 (AB4 가 양방향 진동)
- **정착 후 장기**: AB4 우세, 한 자릿수 작고 영구 오프셋
- **"전 구간 우세"**: 성립하지 않는다

선택 기준이 "구간 길이"에서 **"초기 최대 excursion 을 중시하는가, 정착 후
장기 오차를 중시하는가"** 로 바뀐다.

## 적분기 선택 — 갱신된 상태

후보는 여전히 **AB2/Buss2 와 AB4/Buss2** 이며 어느 쪽도 유력이라 부르지
않는다. 다만 판단 근거가 바뀌었다:

- acc02 **누적** KE 지표에서 AB2/AB4 교차가 4~5초에 관측됐다
- 최초 excursion 최대값은 둘이 같고(2.313e-08), 정착 후에는 AB4 가 한
  자릿수 작은 영구 오프셋이라 예측 가능하다
- acc03 은 RectEuler 만 구분하고 나머지 셋을 가르지 못한다
- 비용 차이 없음, 정확 직렬화 반복성 넷 다 확보

**선택에는 구간 길이만으로 부족하다.** 대표적인 모멘트 변화와 제어 입력의
매끄러움을 함께 봐야 한다 — acc02·acc03 은 둘 다 제어 입력이 없다.
ADR 에서 결정한다.

## 강제응답 시험 — 재구성 (2026-08-15)

**첫 판의 결과와 "C² 명령이 5.7배 정확하다"는 결론은 철회한다.** 두
계산기가 서로 다른 입력을 풀고 있었다.

### 첫 판의 결함

| # | 결함 |
|---|---|
| 1 | "프로파일을 한 곳에 정의"라고 적어놓고 **C++ 에 다시 구현**했다. 서술 자체가 거짓이었다 |
| 2 | JSBSim 은 dt 마다 갱신하고 유지하는 **ZOH**, DOP853 은 연속 함수 `M(t)` 를 RHS 마다 호출 — **다른 입력** |
| 3 | 계단 불연속에서 DOP853 을 **재시작하지 않았다.** rtol 을 줄여도 낫지 않는다 |
| 4 | 계단과 C² 는 최댓값·총시간만 같고 **절대 임펄스가 다르다** — 매끄러움 덕인지 자극량이 작아서인지 안 갈린다 |
| 5 | **실제 적용 모멘트를 기록하지 않았다.** 일-에너지 검사가 Python 프로파일로 재구성해서, 두 구현이 어긋나도 검출 못 한다 |
| 6 | 계단과 C² 둘로는 **필요한 연속성 차수**를 말할 수 없다 |

### 고친 구조

```
forced_profile.py  →  스케줄 파일 (t, Mx, My, Mz)    ← 유일한 정의
        ↓
   생성기가 소비만 한다 (프로파일 코드 없음)
        ↓
   .mom = JSBSim 이 **실제 적용한** 외부 모멘트, 매 스텝
        ↓
   DOP853 이 그 로그를 ZOH 로 재생, 매 구간 경계에서 재시작
```

명령값과 실제 외부 모멘트를 **매 스텝 재폐쇄**한다(1e-9 상대). 이 검사가
바로 값을 했다 — 편집 중 모멘트 적용 코드가 사라진 것을 잡아냈고,
"한 스텝 지연"으로 오인했던 것도 그 탓이었다.

프로파일은 넷: `step` · `c0ramp`(선형) · `c1ramp`(3차) · `c2ramp`(5차).

### 표 1 — 동일 입력에서 AB2 대 AB4 (T=6, dt 0.001)

| 프로파일 | 적분기 | 각거리 max | RMS | ‖Δω‖ max | 일-에너지 |
|---|---|---|---|---|---|
| step | AB2 | 8.131e-02 | 5.078e-02 | 1.738e-03 | 5.866e-03 |
| step | AB4 | 8.190e-02 | 5.097e-02 | 1.741e-03 | 5.865e-03 |
| c0ramp | AB2 | 6.546e-02 | 4.221e-02 | 1.596e-03 | 1.051e-03 |
| c0ramp | AB4 | 6.577e-02 | 4.231e-02 | 1.598e-03 | 1.050e-03 |
| c1ramp | AB2 | 6.782e-02 | 4.304e-02 | 1.622e-03 | 1.062e-03 |
| c1ramp | AB4 | 6.814e-02 | 4.314e-02 | 1.624e-03 | 1.062e-03 |
| c2ramp | AB2 | 6.888e-02 | 4.342e-02 | 1.634e-03 | 1.067e-03 |

**AB2 와 AB4 는 여전히 갈리지 않는다** — 모든 프로파일에서 차이가 0.7%
수준이고 AB2 가 근소하게 앞선다.

**"C² 가 5.7배" 는 사라졌다.** 동일 입력에서 step 대 c2ramp 는 **1.18배**

### 표 2 — 절대 임펄스를 맞춘 매끄러움 시험 (AB4/Buss2)

| 프로파일 | 각거리 max | RMS | ‖Δω‖ max |
|---|---|---|---|
| **step** | **8.190e-02** | 5.097e-02 | 1.741e-03 |
| c0ramp | 9.554e-02 | 5.228e-02 | 2.300e-03 |
| c1ramp | 9.068e-02 | 5.053e-02 | 2.046e-03 |
| c2ramp | 8.802e-02 | 4.962e-02 | 1.973e-03 |

자극량을 맞추자 **이점이 뒤집힌다** — 계단이 가장 정확하고, 램프 안에서는
연속성 차수가 높을수록 낫다(c0 → c2 로 9.554 → 8.802e-02).

즉 표 1 에서 램프가 나아 보였던 것은 **매끄러움이 아니라 임펄스가 작아서**
였다. 같은 임펄스라면 계단이 오히려 낫다.

**철회**: "매끄러운 명령이 적분기 선택보다 5.7배 크게 작용한다"는 결론은
근거가 없다. 동일 입력·동일 임펄스로 재면 그 효과는 최대 16% 이고 방향도
첫 판과 반대다. 제어 법칙을 C² 로 설계할 근거는 **이 시험에서 나오지
않는다** — 매끄러움의 이유는 적분 정확도가 아니라 다른 데 있어야 한다.
