# JSBSim 연동 프로브 (계약 2 평가용)

`docs/transition_phase_contract.md` §11.5의 채택 절차 중 **2단계**(공개
순전파 모델의 C++ 연동·PVA 추출 가능성 확인)를 재현 가능한 형태로 고정한
실험이다. ROS2 빌드 그래프에 **포함되지 않는다** — 플래너는 JSBSim에
의존하지 않으며, 전환 모델 스펙이 확정되기 전에 `src/`가 이것을 링크하기
시작해서는 안 된다.

## 실행

```bash
./run.sh                      # 고정 버전 내려받아 빌드하고 둘 다 실행
./run.sh --model X15          # 다른 번들 예제 기체
./run.sh --version v1.2.1     # 다른 태그로 재검증
```

`run.sh`가 JSBSim을 `.jsbsim/`(gitignore)에 받아 빌드하고, RPATH를 박아
실행한다. `LD_LIBRARY_PATH`를 손으로 설정할 필요가 없다 — 초판 실험은 그게
필요해서 "빌드된다"와 "실행된다"가 서로 다른 주장이었다.

## 버전 고정 근거

`v1.3.1` (현재 안정 릴리스). 처음 측정한 `v1.2.1`도 동일하게 빌드·실행되며
수치도 같은 자리에서 나온다. 굳이 옛 버전을 붙들 이유가 없어 최신으로
올렸고, `--version`으로 언제든 되돌려 확인할 수 있다.

## 이 실험이 **주장하지 않는** 것

번들 예제 기체(f16, X15 등)는 JSBSim 프로젝트가 **공개 자료로 만든 근사
모델이며 교육·오락 목적**이라고 명시한 것들이다. 따라서 여기 나오는 모든
수치는 **구조와 계산비용**에 대한 것이지, 실제 플랫폼의 비행 가능성에
대한 것이 아니다 (계약 문서 §11.3의 "물리 타당성 층"은 여전히 비어 있다).

특히 `jsbsim_probe`의 4단계 격자 탐색이 찾는 것은 **부분 인계창**
(속력 + 비행경로각) 도달일 뿐이며, **인계 성공이 아니다.** 실제 인계에는
아래가 모두 필요하고 여기서는 하나도 검사하지 않는다:

- `pvaEnvelopeProblem()` 통과
- 전역 경로 진입점과의 위치 정합 (`route_start_s`)
- 경로 접선과 속도 방향 정렬
- 가속도·하중 조건
- 인계 영역 체류
- 지형·구역 검사

## 측정 결과 (v1.3.1, f16, 12 s)

**연동·비용**

| 항목 | 값 |
|---|---|
| 빌드·링크 | ROS2 Humble 컨테이너에서 무경고, 외부 의존 libstdc++/libm/libgcc/libc |
| 라이브러리 | 3.4 MB (+ 항공기 데이터 4 MB) |
| 스텝당 비용 | 8.7~9.7 µs (12 s 궤적 = dt 0.01에서 11 ms) |
| 적분 스텝 민감도 | dt 0.001→0.02에서 12 s 후 고도차 0.3 m |
| 재현성 | 동일 프로파일 2회 비트 단위 일치 |
| 부분 인계창 격자 탐색 | 27 프로파일 × 30 s를 761 ms에, 15개 도달 |

**로컬 프레임 가속도 — 어떤 식이 맞는가**

`FGAccelerations::CalculateUVWdot`은 `vUVWdot`을 **동체 성분의 변화율**로
계산한다(수송항 `(vPQR + 2·Ti2b·ω_planet) × vUVW`를 이미 빼놓았다).
따라서 `Tb2l * UVWdot`은 d(V_local)/dt가 아니다. 실측:

| 식 | 속도 중앙차분과의 최대 격차 |
|---|---|
| `Tb2l * (UVWdot + PQR × UVW)` | 0.12 m/s² (피크의 **1.4%**) |
| `Tb2l * UVWdot` (FGStateSpace가 쓰는 형태) | 4.52 m/s² (피크의 **53.3%**) |

수송항을 되돌린 쪽을 쓴다. 중앙차분은 교차검증용으로만 남긴다.

**PVA → 5차 Hermite 재표현**

| 항목 | 결과 |
|---|---|
| knot P/V/A 일치 | 1e-14 이하 (구성상 정확) |
| 조각 간 C⁰/C¹/C² | 0 / 7e-15 / 1e-13 |
| 구간 내부 위치 오차 | knot 0.1 s에서 8 mm, 0.5 s에서 41 mm, 2 s에서 0.39 m — 수렴 |
| 구간 내부 속도 오차 | **knot 간격과 무관하게 ~1.03 m/s** |
| 구간 내부 가속도 오차 | 촘촘할수록 **악화** (0.1 s에서 31.9, 1 s에서 3.2 m/s²) |
| jerk | 피크 529 m/s³, 접합 점프 35.6 m/s³ — **측정만**, 상한은 스펙 대기 |

속도 오차가 수렴하지 않는 이유가 이 실험의 핵심 발견이다. 소스 삼중항이
스스로 어긋나 있다: `|d(p)/dt − v| = 0.554 m/s` (속력의 0.29%). 위치와
속도를 **양 끝에서 동시에** 고정한 5차 다항식은 구간 안에서 그만큼의 여분
이동을 흡수해야 하므로, 중간 속도가 약 2ε만큼 초과한다 — 구간 길이와
무관하게. 실측 1.03 ≈ 2 × 0.554로 예측과 일치한다.

원인은 이 프로브의 좌표 변환이다: 지심위도 + 구면 반지름 평면근사.
**해결은 knot을 촘촘히 하는 게 아니라 상류의 타원체 국소접평면 변환**이다.
계약 2에서 프레임 변환은 각주가 아니라 어댑터의 **지배적 오차원**으로
다뤄야 한다.

가속도 오차가 촘촘할수록 커지는 것은 별개의 다항식 성질이다. 짧은 구간에서
양 끝 가속도를 정확히 맞추려면 5차식이 안쪽에서 크게 출렁이며, jerk 피크
529 m/s³이 그 결과다. §6이 요구하는 "구간 내부 극값 검사"가 왜 필요한지를
보여주는 실측 사례다.
