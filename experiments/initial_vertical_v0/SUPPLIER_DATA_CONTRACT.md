# 6DOF 데이터 공급 계약과 검증 절차

**초안. 공급자와 합의 전이다.**

이 문서는 공력·질량 자료를 **받을 형식**과 **받은 뒤 검증할 절차**를
정한다. 계수를 추측하지 않고, 자료가 오면 그대로 판정할 수 있게 하는 것이
목적이다.

문헌 탐색과 계수 추측은 종료했다([SOURCE_GAP.md](SOURCE_GAP.md)).
현재 공급자는 fail-closed 이며 물리적 성립성은 UNKNOWN 이다.

이 계약이 완성되면 선택지가 명확해진다.

| 상황 | 다음 |
|---|---|
| 공급자가 자료를 입력 | 실제 모델 판정 진행 |
| 제공이 늦음 | CFD·별도 시험을 **독립 마일스톤**으로 수행 |
| 둘 다 없음 | 물리적 성립성 계속 UNKNOWN |

---

## 0. 전제 — 무엇이 이미 정해져 있나

받는 쪽이 이미 고정한 것들이다. 공급자가 다른 규약을 쓰면 **변환은 받는
쪽이 하고, 변환식을 이 문서에 적는다.**

| | 값 | 출처 |
|---|---|---|
| 중기 포락선 | `optimizer_params.yaml` 의 `dynamics_*` | 생산 설정 |
| 순항 하한 | `speed_min × (1 + margin)` = 131.76 m/s | 같은 곳 |
| 인계 상한 | `min(speed_max, max_vel × unit)` = 200.0 m/s | 같은 곳 |
| 목표 마하 대역 | 0.3585 ~ 0.7000 | 122 m/s(해면) ~ 230 m/s(3000 m) |
| 인계 판정 | `mmp_vehicle_dynamics::handoffVerdict` | 생산과 **같은** 함수 |
| 체류 | 1.0 s 연속 (실험 초깃값) | `params_declared_test.txt` |

**시험·인터페이스 검증용 기준 형상**은 NACA TR 1096 을 `S = 1.0 m²` 로
스케일한 것이다. **실제 기체 형상이 아니다** — 배관과 계약을 검증할
대상이며 실기 형상이 오면 교체된다.

## 1. 질량·CG·관성

### 입력 형식

| 항목 | 단위 | 필수 |
|---|---|---|
| 질량 | kg | 필수 |
| CG 위치 | m, 기준점 명시 | 필수 |
| `Ixx` `Iyy` `Izz` | kg·m² | 필수 |
| `Ixz` (및 `Ixy` `Iyz`) | kg·m² | 필수 — 0 이면 0 이라고 적을 것 |

### 시간 변화

연료 소모·분리 등으로 변하면 **변화를 표로** 준다. 상수면 상수라고
명시한다. "대략 일정" 은 받지 않는다 — 판정기가 그 말을 쓸 수 없다.

```
t[s] | mass[kg] | cg_x[m] cg_y cg_z | Ixx Iyy Izz Ixz [kg·m²]
```

### 기준점

CG 좌표와 관성의 기준점을 **명시**한다. 기준점이 다르면 평행축 정리로
옮기고, 그 변환을 기록한다.

> 현재 선언값(`iyy 4200 kg·m²` 등)은 **근거 없는 시험값**이다. 실제
> 자료가 오면 대체된다. 무차원 관성 `Iyy/(m c̄²)` 은 기준길이와 함께
> 보고한다 — 기준길이 없는 무차원 관성은 비교 불가다.

## 2. 공력 계수 표

### 필요한 계수

| 계수 | 축 | 비고 |
|---|---|---|
| `CL(α, M)` | α, M | **비선형 영역 포함** |
| `CD(α, M)` | α, M | 또는 `CD(CL, M)` — 어느 쪽인지 명시 |
| `Cm(α, M)` | α, M | 모멘트 기준점 명시 필수 |
| `Cm_q(α, M)` | α, M | **단독**. 합이면 §2-4 참조 |
| `Cm_αdot(α, M)` | α, M | 단독 |
| `Cm_δe(α, M)` | α, M | 제어면이 있으면 |

`CL_max(M)` 은 표에서 유도하지 말고 **따로** 준다 — 표 끝값이 최대라는
보장이 없다.

### 표 축과 보간 규칙

- 축은 **단조 증가**, 중복 없음
- α 축은 **부호 있는 범위**. 양의 값을 반사해 음수로 만들지 않는다
  (기준 형상 실측이 `CL(0) = +0.005`, `Cm(0) = +0.019` 로 영점에서조차
  홀대칭이 아니다)
- 보간: **선형** 기본. 다른 방식을 쓰려면 명시하고 근거를 적는다
- **외삽 금지.** 축 밖은 fail-closed (§5)
- 결측 칸은 빈칸이 아니라 `UNKNOWN` 으로 표기. 0 으로 채우지 않는다

### 등급

값마다 출처 등급을 붙인다. 등급 없는 수는 받지 않는다.

| 등급 | 뜻 |
|---|---|
| `MEASURED` | 풍동·비행시험 실측. 시험 조건(Re, 난류도, 지지간섭 보정)을 함께 |
| `MEASURED_DIGITIZED` | 그림 판독. **판독 오차**를 함께 |
| `CFD` | 해석. 격자·난류모델·수렴 기준을 함께 |
| `ESTIMATED` | 해석식·유추. 방법과 적용범위를 함께 |
| `UNKNOWN` | 미상 |

### 2-4. 감쇠 합만 있는 경우

`Cm_q` 와 `Cm_αdot` 은 일반 운동방정식에서 **서로 다른 입력**에 곱해진다:

```
Cm_q      →  q c̄ / (2V)        (몸체 피치율)
Cm_αdot   →  α̇ c̄ / (2V)        (받음각 변화율)
```

강제진동 시험이 합만 내는 것은 그 시험에서 두 입력이 묶여 움직이기
때문이지 물리적으로 하나여서가 아니다. 따라서 합만 오면:

- **합으로 표기해서** 받는다 (`Cm_q_plus_alphadot`)
- `Cm_q` 로 변환하지 않는다
- **그 시험 조건에서의 총 감쇠 진단에만** 쓴다
- 일반 6DOF 전파에는 두 항이 분리되기 전까지 `UNKNOWN`

받는 쪽 코드가 이것을 타입으로 강제한다
([v0_aero.hpp](v0_aero.hpp) 의 `PitchDampingAlone` / `PitchDampingSum`).

## 3. 좌표계·부호·단위·무차원화

**받는 쪽 규약을 먼저 적고, 공급자 규약과 다르면 변환식을 기록한다.**
이 절이 비면 나머지 전부가 무의미하다 — 57.3 배나 2 배 오류는 여기서
난다.

| 항목 | 받는 쪽 규약 |
|---|---|
| 몸체 좌표계 | X 전방 · Y 우현 · Z 하방 |
| 각도 단위 | **라디안** (표는 도 가능, 단위를 열 이름에 명시) |
| `CL_α` 등 기울기 | per **radian** (표가 per degree 면 명시) |
| 피치율 무차원화 | `q c̄ / (2V)` — `q c̄ / V` 아님 |
| 기준면적 `S` | **양력 기준면적**. 생산 `wing_area_m2` 와 같아야 함 |
| 기준길이 `c̄` | 날개 평균공력시위 |
| 모멘트 기준점 | CG. 다르면 위치를 명시하고 이송 |
| 대기 | 표준대기. 밀도를 함께 주면 그것을 쓴다 |

### 알려진 함정

- `Cm_q` 는 `/rad` **값이 아니다**. `q c̄/(2V)` 로 정규화된 무차원
  미계수다. `/rad` 인 것은 `CL_α` 쪽이다
- 문헌이 `q l / V`(반감 없음)를 쓰고 기준길이가 **루트시위**인 경우가
  있다. 그러면 표준형으로 옮길 때 `2 (c₀/c̄)²` 가 붙는다
- 기준면적을 동체 단면적으로 주면 CL 이 배수만큼 어긋나 `CL_max` 상한에
  걸리지 않는다 — 받는 쪽이 일치를 강제한다

## 4. 조종 입력과 힘·모멘트 출력 계약

### 입력

| 항목 | 단위 | 비고 |
|---|---|---|
| 승강타 편향 `δe` | rad | 부호 규약 명시 |
| 추력 `T` | N | 방향(몸체축) 명시 |
| 편향률 한계 | rad/s | 액추에이터 |
| 편향 한계 | rad | 포화 |

제어면 계수를 공개하지 않으면 §8 의 외부 모듈로 받는다.

### 출력

```
힘   F_body = [Fx, Fy, Fz]   N   (몸체축)
모멘트 M_body = [Mx, My, Mz]   N·m (CG 둘레, 몸체축)
```

**공급자가 계수 표를 주든 모듈을 주든 이 출력 계약은 같다.**

## 5. 유효 범위와 fail-closed

### 명시할 것

| 항목 | 형식 |
|---|---|
| 마하 유효 범위 | `[M_min, M_max]`, 검증된 근거와 함께 |
| 받음각 유효 범위 | `[α_min, α_max]` — **부호 있는** |
| 옆미끄럼각 유효 범위 | `[β_min, β_max]` |
| 고도·레이놀즈수 범위 | 있으면 |
| 파탄 조건 | 실속·박리·충격파 발생 등. 없으면 "없음" 이라고 적을 것 |

> "아공속 전 범위" 같은 정성적 진술은 유효 범위가 아니다. 도표점만 있고
> 사이가 비어 있으면 그 사실을 적는다.

### 범위 밖 처리 — **fail-closed**

받는 쪽은 범위 밖에서 **값을 내지 않고 거부한다.** 외삽하지 않는다.
현재 구현이 이미 그렇다:

```
v0aero::requireInBand(mach, ...)      → OutOfRange
v0aero::liftSlopeRatio(...)           → Unavailable (출처 감사 전)
v0aero::pitchDampingInBand(...)       → Unavailable (대역 내 UNKNOWN)
```

거부 사유는 이름 있는 열거형으로 낸다(`HandoffReject`, `EnvelopeLimit`).

## 6. 검증 — **네 검사를 분리한다**

허용폭 하나로 모든 오차를 합치면 안 된다. 합치면 불일치가 나왔을 때
**구현 오류인지 기체 차이인지 가릴 수 없다.** 네 가지는 목적도 대상도
허용오차도 다르다.

| # | 검사 | 대상 | 허용오차 | 합격 판정에 쓰나 |
|---|---|---|---|---|
| 6-1 | 규약 검사 | 아무 모델이나 | **엄격** (수치 오차 수준) | **예** |
| 6-2 | 공급자 재현 | 산업체 실모델 | 공급자가 제시 | **예** |
| 6-3 | 공개 자료 대조 | **검증용 형상만** | 판독 오차 + 별도 합의 | 예 (검증용 형상에 한해) |
| 6-4 | 실기 vs 공개 자료 | — | — | **아니오** |

### 6-1. 규약 검사 — 단위·축·부호·무차원화

**엄격한 수치 검사**다. 여기서 잡는 것은 물리 차이가 아니라 **배관 오류**
이므로 허용오차가 좁아야 한다. 이번 작업에서 실제로 나온 오류가 전부 이
범주였다: per degree 를 per radian 으로 읽어 57.3 배, `q c̄/(2V)` 를
`q l/V` 로 읽어 2 배와 기준길이비 제곱, 양력 기준면적에 동체 단면적을
넣어 3.537 배.

검사 항목:

- 알려진 단순 상태에서 힘·모멘트의 **부호**가 맞는가
  (예: 양의 받음각에서 양력이 위쪽, 안정한 기체는 `Cm` 이 음의 기울기)
- 무차원화를 **역으로 풀어** 원 계수가 복원되는가
  (`M = q S c̄ Cm` 에서 `Cm` 을 되돌려 입력과 일치)
- 각도 단위를 바꾼 입력이 **정확히 57.3 배** 관계로 나오는가
- 피치율 무차원화를 바꾸면 **정확히 2 배**(및 기준길이비) 관계인가
- 기준면적·기준길이를 바꾸면 그 비율대로 스케일되는가

이 검사는 **어떤 모델에도** 적용된다. 실기 모델이든 검증용 형상이든
규약은 같아야 한다.

### 6-2. 공급자 재현 검사 — 기준 벡터

**내부 계수를 공개하지 않아도 된다.** 대신 기준 사례를 요청한다:

```
입력   상태 (V, alpha, beta, p, q, r, alpha_dot)
     + 환경 (고도, 밀도 또는 마하, 동압)
     + 조종 입력 (승강타, 추력)
출력   기대 힘·모멘트 (몸체축, CG 둘레)
     + 질량·CG·관성
     + 각 출력의 허용오차
```

받는 쪽은 이 기준 벡터를 넣어 같은 값이 나오는지 본다. 나오면 **좌표계와
배관이 맞는다**는 뜻이고, 그것이 이 검사의 전부다. 물리의 정확성은 이
검사가 말하지 않는다.

기준 벡터는 **유효 범위의 경계와 안쪽**을 함께 덮어야 한다. 경계 밖
사례도 하나 이상 포함해 `in_range = 0` 이 실제로 나오는지 확인한다.

### 6-3. 공개 자료 대조 — **검증용 형상에만**

TR 1096 겹침 조건은 **검증용 형상을 넣었을 때** 배관과 규약이 맞는지
확인하는 용도다.

```
형상   TR 1096 의 W + F2 + V + H2 (A 4.0, 테이퍼 0.6, 1/4시위 45°,
       65A008, S_H/S_W 0.20, l/c̄ 1.8172, i_H 0°)
조건   M = 0.13, Re = 0.71×10⁶ (날개 MAC 기준)
기준   모멘트 0.25 c̄
```

| 항목 | 기준값 (M=0.13) | 판독 오차 |
|---|---|---|
| `CL(α)` α = −2…20° | [SOURCES.md](SOURCES.md) §2 표 | ±0.010 (α≥6), ±0.015 (α≤4) |
| `Cm(α)` 같은 범위 | 같은 표 | ±0.005 |
| `CL_α` (−2…8° 회귀) | 0.06328 /deg | 구간 선택으로 0.06311~0.06354 |
| `Cm_q` 전체 형상 | −5.48 | ±0.05 |
| `Cm_q` 날개+동체 | −2.00 | ±0.10 |

위 허용오차는 **판독 오차만**이다. 형상 오차·레이놀즈수 차이·지지간섭
보정은 들어 있지 않으므로, 대조 허용폭은 공급자와 **별도로 합의**한다.

### 6-4. 실기 형상은 TR 1096 과 대조하지 않는다

**산업체 실모델을 TR 1096 값과 직접 대조하면 안 된다.** 서로 다른
형상이므로 차이가 나와도 **구현 오류인지 기체 차이인지 구분할 수 없다.**
그 차이를 합격·불합격에 쓰면 잘못된 신호를 준다 — 맞으면 우연이고,
틀리면 원인을 모른 채 반려하게 된다.

실기 모델의 정확성은 6-2(공급자 재현)와 공급자 자신의 검증 자료가
말한다. TR 1096 은 배관 검증용이지 실기 판정 기준이 아니다.

### 대조가 실패하면

값을 조정해 맞추지 않는다. **불일치를 기록하고 멈춘다.** 어느 쪽이 틀린
것인지 가리는 것이 먼저이고, 6-1~6-4 를 분리해 둔 이유가 그것이다 —
어느 검사에서 걸렸는지가 곧 원인의 범주다.

> 선례: 식 (3) 이 실측 구성 증분을 17.5% 과대예측했을 때 경험 인자
> 0.85 를 걸지 않고 폐쇄 실패로 기록했다([SOURCES.md](SOURCES.md) §3).

## 7. 인계 검증 절차

§6-1(규약)과 §6-2(공급자 재현)를 통과한 뒤 실행한다. §6-3(공개 자료
대조)은 **검증용 형상일 때만** 선행 조건이고, 실기 형상에는 적용하지
않는다(§6-4).

1. 계수를 공급자에 주입하고 **적용 범위를 등록**한다
2. `run_cases.sh` 전 사례 통과 확인 (현재 7/7)
3. 수직 사례 재실행 — 결합 관문 두 단계 판정
4. **적용범위 창** 재측정 — 궤적이 공급된 범위 안에 얼마나, 그리고
   **연속으로 얼마나** 머무는지. 연속시간이 체류 요구 미만이면 인계
   불가이며, 그것은 모델 실패가 아니라 범위 부족이다
5. 요구조건 역산 A 를 실제 계수로 다시 돌려 **직접 전환** 여부 확인

각 단계의 판정은 구조화 출력으로 내고 회귀가 값으로 단언한다.

## 8. 계수를 공개하지 않는 경우 — 외부 모듈 인터페이스

공급자가 표를 못 주면 **모듈**로 받는다. 계수는 모듈 안에 남고, 받는
쪽은 힘·모멘트만 본다.

### 최소 인터페이스

```c
// 상태를 넣고 몸체축 힘·모멘트를 받는다. 계수는 노출하지 않는다.
typedef struct {
  double mach, alpha_rad, beta_rad;
  double p, q, r;              // rad/s, 몸체축
  double alpha_dot_rad_s;
  double qbar_pa, altitude_m;
  double elevator_rad, thrust_n;
} SupplierState;

typedef struct {
  double force_body_n[3];      // X 전방 · Y 우현 · Z 하방
  double moment_body_nm[3];    // CG 둘레
  int    in_range;             // 0 이면 아래 사유가 채워진다
  char   out_of_range_reason[128];
} SupplierOutput;

int supplier_evaluate(const SupplierState *in, SupplierOutput *out);
```

### 모듈에도 요구하는 것

- **범위 밖에서 값을 내지 않는다.** `in_range = 0` 과 사유를 낸다
- 결정론적이어야 한다 — 같은 입력에 같은 출력
- §6 겹침 대조를 모듈로도 통과해야 한다
- 질량·관성은 §1 형식으로 **별도** 제공 (모듈 안에 숨기지 않는다)
- 모듈의 유효 범위를 문서로 명시 (§5)

### 받는 쪽이 확인할 것

모듈은 내부를 볼 수 없으므로 **경계에서** 검사한다:

- 겹침 대조 통과 여부
- 범위 경계에서 `in_range` 가 실제로 0 이 되는지 (음성대조)
- 같은 입력 반복 시 출력이 같은지
- 힘·모멘트가 유한한지
- 부호 규약이 맞는지 — 알려진 상태 몇 개로 확인

## 9. 공급자 합의 항목 — **다음 단계는 구현이 아니라 합의다**

아래가 정해지기 전에는 구현을 진행하지 않는다.

| 항목 | 정할 것 |
|---|---|
| 제공 형태 | 표·파일인가 실행 모듈인가 (§2 vs §8) |
| 기준 사례 | 기준 입력·출력 벡터를 제공하는가 (§6-2). 유효 범위 경계와 안쪽, 범위 밖 사례 포함 |
| 허용오차 | **각 출력마다.** 힘·모멘트를 한 값으로 묶지 않는다 |
| 범위 밖 동작 | 거부인가, 포화인가, 사유를 내는가 (§5) |
| 버전 식별 | 자료·모듈의 버전과 **변경 식별 방식**. 값이 바뀌었는데 같은 버전이면 이전 판정이 무효가 된다 |

버전 식별은 특히 중요하다. 받는 쪽 회귀가 값을 단언하므로, 자료가 바뀌면
회귀가 깨져야 하고 그때 **무엇이 바뀌었는지** 알 수 있어야 한다.

## 10. 합의 전까지의 상태

- 공급자 fail-closed 유지
- 물리적 성립성 **UNKNOWN**
- 문헌 탐색·계수 추측 **중단**
- 기준 형상은 **시험·인터페이스 검증용**이며 실기 형상이 아님

이 문서에 합의 서명이 붙기 전까지 위 상태를 바꾸지 않는다.
