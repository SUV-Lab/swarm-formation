# ADR-0003: 수직 발사 자세전환 구간의 6DOF 모델 (초안)

- 상태: **초안 — 승인 전. 구현 착수 금지.**
- 제안 2026-08-14. 브랜치 `lgh/vertical-launch-6dof`.
- 관계: ADR-0002를 **대체하지 않는다.** 순항·완만한 초기 구간은 3DOF
  중립 벤치마크를 그대로 쓴다. 이 문서는 ADR-0002가 스스로 예고한 확장이다
  — *"준수직 발진이 요구되면 모델 확장이 필요하며 가드가 조용히 흡수하게
  두지 않는다."*
- ADR-0001의 기각 사유 6개를 통과해야 한다. §7에 항목별로 대조한다.

## 0. 범위 선언 (모든 산출물 필수 표기)

> **공개 참조 모델 기반 구조 검증**이며, 실제 플랫폼 물리 검증이 아니다.
> 특정 업체·플랫폼의 성능을 주장하지 않는다.

명시적 제외: 특정 플랫폼 성능 추정, 표적 관련 기능, 제한 도메인 고유명사.

---

## 1. 해결하려는 문제

정확히 수직인 초기 상태에서 출발해 자세를 점진적으로 기울이고, 기존 중기
궤적에 연결한다.

```
수직 (상승각 90°)  →  자세 전환  →  완만한 상승각  →  중기 경로 정렬
```

**요구하지 않는 것**: 수직을 넘어가는 루프. 상승각은 90°에서 단조 감소만
한다.

### 현행 3DOF로 불가능한 이유 (측정치)

| 벽 | 값 | 성격 |
|---|---|---|
| 기동 조각 목록 | 최대 +20° | 코드 상수 `kGammaTargetsRad` |
| 모델 상승각 상한 | 30° | 설정 `dynamics_flight_path_max_deg` |
| 초기 구간 허용 상한 | 80.21° | 코드 상수 `max_abs_gamma_rad{1.40}` |
| **수식 한계** | **87.13°** | `acos(kMinCosGamma)`, 0.05는 사람이 그은 선 |
| 추진 | T/W = 0.25 | 유지 상승 한계 ≈ 14.5° (항력 제외) |

앞의 넷은 값이다. 마지막 벽만 형식 문제다: 방위각 변화율이
`… / cos(상승각)`이라 수직에서 0으로 나눈다. 지구본의 극점에 경도가 없는
것과 같은 문제이며, 값을 낮춰 피할 수 없다.

같은 물리 기동(속도 벡터를 초당 1° 옆으로)을 방위각 변화율로 환산하면:

| 상승각 | 방위각 변화율 | 한 적분 단계(0.05 s) |
|---|---|---|
| 80° | 5.8 °/s | 0.3° |
| 87.13° | 20 °/s | 1.0° |
| 89° | 57 °/s | 2.9° |
| 89.9° | 573 °/s | **28.6°** |

**결론: 각도 좌표를 확장하지 않는다.** 요청대로 위치·속도벡터·쿼터니언·
각속도·질량을 상태로 갖는 별도 모델을 쓴다.

## 2. 결정 (제안)

### 2-1. 물리 엔진: JSBSim 라이브러리 + **자체 작성 중립 기체 정의**

라이선스를 실물로 확인했다(`logs/jsb131`, 1.3.1):

| 대상 | 라이선스 | 근거 |
|---|---|---|
| 라이브러리 | **LGPL 2.1** | `COPYING` |
| 번들 기체 데이터 파일 | **GPL** (자체 fileheader 선언) | 전수 확인: 12개 기체 전부 `licenseName="GPL"` |

ADR-0001의 기각 사유 3(라이선스 오기)이 사실로 확인됐다. **둘은 별개다.**

따라서:

- **라이브러리는 링크한다** — LGPL 2.1, 동적 링크 시 우리 코드에 전염 없음
- **번들 기체 데이터는 쓰지 않는다** — GPL이고, 이름이 전부 특정 플랫폼이며,
  ADR-0002가 이미 "전이 영역과 체급을 동시에 만족하는 중립 모델 없음"으로
  전수 조사를 끝냈다
- **기체 정의 XML을 우리가 작성한다** — 서드파티 데이터 파일 0. ADR-0002가
  라이선스·명명 문제를 원천 차단했던 그 성질을 그대로 유지

얻는 것:

| | |
|---|---|
| 검증된 6DOF 적분기 | 쿼터니언 자세, 각속도, 극점 없음 |
| `FGRocket` + `FGTank` | 로켓 추진 및 추진제 소모에 따른 질량 변화 — 요청의 "일반 추진·질량 변화 모델" |
| 좌표 변환 | `jsbsim_probe`가 ECEF→ENU 단일 프레임 변환을 이미 해결·교차검증 |

### 2-2. 기각한 대안

**A. 자체 6DOF 강체 방정식 작성**
방정식은 교과서 공개라 쓸 수 있다. 그러나 데이터 공백은 B와 동일하고,
검증된 적분기·로켓 엔진·탱크를 직접 만들어야 한다. **B가 A를 지배한다.**

**C. JSBSim + 번들 기체 데이터**
ADR-0001이 기각한 경로. GPL 데이터, 명명 충돌, 체제 불일치. 재검토하지
않는다.

### 2-3. 감수하는 비용 — 물리 권위가 둘이 된다

ADR-0002의 강점 중 하나가 "전환·순항이 같은 공식·같은 `Parameters`"였다.
JSBSim을 들이면 물리 구현이 둘이 된다.

완화: **구간별 권위**로 재정의한다. 인계는 PVA + C²로만 이뤄지므로 두 모델이
같은 공식일 필요는 없다. 대신 **인계점에서 양쪽 모델이 같은 상태를 각자
유효하다고 판정하는지** 검사한다(§4-5).

부수 효과: ADR-0002는 JSBSim 프로브를 "독립 민감도 비교용, **합격 판정자
아님**"으로 규정했다. 이 결정은 그 지위를 바꾼다 — 신규 구간에 한해
판정자가 된다. **명시적 지위 변경이며, 승인 대상이다.**

## 3. 데이터: 있는 것과 없는 것

### 3-1. 현재 보유 (ADR-0002 중립 baseline)

```
질량 1300 kg, 날개면적 1 m², CD0 0.035, k 0.080, CLmax 1.40, 추력 0–3200 N
```

### 3-2. 6DOF에 추가로 필요한 것 — **전부 없음**

| 분류 | 파라미터 | 보유 |
|---|---|---|
| 관성 | Ixx, Iyy, Izz, Ixz | ✗ |
| 기준 치수 | 날개 스팬 b, 평균공력시위 c̄ | ✗ |
| 세로 모멘트 | Cm0, Cmα, Cmq, Cmδe | ✗ |
| 가로 모멘트 | Clβ, Clp, Clr, Clδa, Clδr | ✗ |
| 방향 모멘트 | Cnβ, Cnp, Cnr, Cnδa, Cnδr | ✗ |
| 측력 | CYβ, CYδr | ✗ |
| 양력의 α 의존 | CL0, CLα, α_stall | ✗ (CLmax만 있음) |
| 제어면 | 편향 한계, 편향 속도, 액추에이터 시정수 | ✗ |
| 추진 | 추력 프로파일, 연소시간, 추진제 질량, 무게중심 이동 | ✗ |
| 마하 의존성 | 위 계수들의 마하 테이블 | ✗ |

**6개 보유 → 약 25개 필요.**

### 3-3. 공백을 메우는 방법 — 선언된 형상 + 공개 추정법

**임의 값을 넣지 않는다.** ADR-0001의 기각 사유 4가 정확히 그 위험을
지적했다 — *"coarse surrogate를 동일 기체 정합이라 부르는 과장"*. 6DOF는
3DOF보다 이 위험이 크다. 계수가 틀려도 결과가 더 정밀해 **보이기**
때문이다.

제안:

1. **형상을 프로젝트가 선언한다** — 스팬, 시위, 미익 면적·모멘트암, 질량
   분포. ADR-0002가 질량 1300 kg를 선언했던 것과 같은 성격
2. **공개 준경험식으로 계수를 추정한다** — USAF Digital DATCOM 계열
   (형상 입력 → 정·동안정 미계수 출력). 임의 값이 아니라 **선언된 형상 +
   공개 방법**이 된다
3. **관성텐서는 질량 분포에서 계산한다** — 형상과 질량 배치를 선언하면
   유도된다
4. **모든 값에 출처 등급을 붙인다**: `선언` / `추정(방법 명시)` / `미상`

라이선스: Digital DATCOM의 공개 지위는 **재확인 필요**(§8-1). 확인되지
않으면 교과서 준경험식(공개 문헌)으로 대체한다.

### 3-4. 정직성 규칙 (필수)

- 추정 계수로 얻은 결과에 **정밀도를 주장하지 않는다**
- 산출물은 "구조 검증"이라 표기한다. "비행 성능"이라 하지 않는다
- **정책 값을 조기 동결하지 않는다** — ADR-0001 기각 사유 6. 안정 판정
  임계값은 실험 초깃값으로 두고, 생성 결과 분포로 합격선을 정하지 않는다

## 4. 구조

### 4-1. 파이프라인

```
① 6DOF 자세전환 궤적 생성
   수직 초기 상태 → 자세를 점진적으로 기울임 → 중기 경로 방향 정렬

② 안정 영역 진입 판정
   속력 · 자세 · 각속도 · 동압 · 제어 여유
   → 전부 안정 범위에 "일정 시간 연속" 머물렀는가

③ 종료 PVA 추출 및 변환
   6DOF 상태 → (위치, 속도, 가속도) → 기존 Hermite/MINCO 표현

④ 기존 중기 궤적과 C² 연결

⑤ 연결된 전체 궤적을 6DOF 추종 모델로 재검증
```

### 4-2. 재사용 — 기존 코드

| 대상 | 위치 | 재사용 내용 |
|---|---|---|
| 프레임 변환 | `experiments/jsbsim_probe` | ECEF→ENU 단일 프레임. 해석적 가속도 + 중앙차분 교차검증까지 **완료된 자산** |
| 파이프라인 골격 | `transition_phase.cpp` | 진입 후보 열거 → 후보별 전파 → 판정 → 어댑터 → 감사 계수. **모양은 그대로, 안의 적분기만 교체** |
| 결과 계약 | `TransitionResult` | `traj`(5차 조각) + 종료 PVA(SI) + `route_start_s` + 감사. **그대로 쓸 수 있다** |
| Hermite 변환 | `quintic_hermite.h` | 종료 PVA → 5차 조각 |
| C² 연결 | `segment_chain_planner` | 이음매 연속성 검사 포함 |
| 순항측 유효성 | `pvaEnvelopeProblem` | 인계점이 중기 모델에도 유효한지 |
| 감사 계수 | `TransitionAudit` | 게이트별 탈락 집계. 신규 게이트만 추가 |
| 회귀 골격 | `transition_experiment_test` | 결정성·이음매 연속성 검사 패턴 |

### 4-3. 신규 작성

| 대상 | 내용 |
|---|---|
| 중립 기체 정의 | JSBSim XML. 형상·질량·관성·공력·추진. **서드파티 데이터 0** |
| JSBSim 래퍼 | 상태 주입/추출, 결정성 보장(고정 스텝, 난수 없음) |
| 자세전환 유도 법칙 | 수직 → 목표 상승각. 지금의 "상승각 목표 4개 × 뱅크 2단" 대신 자세·각속도 기반 |
| 안정 영역 판정기 | ②. 5개 지표 × 지속시간 |
| 6DOF → PVA 추출 | ③. 프레임·단위 일치 |
| 재검증 통과 | ⑤. 연결된 전체 궤적을 6DOF로 추종 |
| 부스터 분리 모델 | 질량·관성·공력이 불연속으로 바뀌는 시점 처리 (**설계 미정**, §8-3) |

### 4-4. 손대지 않는 것

- `point_mass_eom.hpp` — 3DOF 그대로. 순항이 쓴다
- MINCO 최적화기의 `flightEnvelopePenalty` — 3DOF 역동역학 그대로
- `mmp/initial-planner-rc1` — **동결**

### 4-5. 인계점 이중 판정

두 물리 모델을 쓰는 대가로 검사를 하나 추가한다:

> 인계점 PVA는 **6DOF 모델이 도달 가능하다고 판정**하고, **동시에 3DOF
> 순항 모델이 유효하다고 판정**해야 한다.

한쪽만 통과하는 상태는 인계하지 않는다.

## 5. 안정 영역 판정 (②) — 초기 제안

| 지표 | 의미 |
|---|---|
| 속력 | 순항 모델 유효 범위 안 |
| 자세 | 목표 상승각 근방, 롤 수평 근방 |
| 각속도 | 충분히 작음 (과도 응답이 끝났는가) |
| 동압 | 제어면이 권한을 갖는 하한 위 |
| 제어 여유 | 편향이 포화에서 떨어져 있음 (여유 없이 유지 중인 자세는 안정이 아니다) |

**5개 전부**가 **연속으로 일정 시간** 유지돼야 한다. 순간 통과는 인정하지
않는다 — 기존 `dwell` 개념과 같은 성격이다.

임계값은 **실험 초깃값**으로 둔다. ADR-0001 기각 사유 6에 따라 이 ADR에서
동결하지 않는다.

## 6. 검증 계획

| 층 | 내용 |
|---|---|
| 단위 | 6DOF 적분기: 무입력 시 보존량, 쿼터니언 정규화, 수직에서 특이점 없음 |
| 일관성 | 완만한 구간에서 6DOF와 3DOF가 같은 답을 주는가 (인터페이스 검사이지 물리 교차검증이 아님 — ADR-0002의 명명 규칙 유지) |
| 계약 | 인계점 C² 연속, 양쪽 모델 동시 유효 |
| 종단 | 수직 → 전환 → 중기 → 완주. 전체를 6DOF로 재추종 |
| 음성 | 안정 영역에 못 드는 초기 상태는 **거절**한다. 조용히 근사하지 않는다 |
| 변이 | 신규 게이트마다 제거 변이가 검사를 죽이는지 확인 (`finalclear` 선례) |

기존 회귀 **69/69 · risk 154/0 · ctest 10/10**은 이 작업 중 계속 통과해야
한다. 3DOF 경로를 건드리지 않는다는 것의 증거다.

## 7. ADR-0001 기각 사유 대조

| # | 기각 사유 | 이 제안의 대응 |
|---|---|---|
| 1 | 단계 의미 불일치 (활주로 기체 → 문제가 "비정상 복귀"로 바뀜) | **해당 없음.** 문제 자체가 수직 발진 → 순항 인계로 명시됐다. 번들 기체를 쓰지 않으므로 체제 불일치가 발생하지 않는다 |
| 2 | 제한 도메인 고유명사 재유입 | **자체 작성 중립 기체.** 번들 기체명이 트리에 들어오지 않는다 |
| 3 | 라이선스 오기 | **실물 확인 완료.** 라이브러리 LGPL 2.1 / 데이터 GPL. 데이터는 쓰지 않고 라이브러리만 링크 |
| 4 | "정합 완료" 과장 | **출처 등급 의무화** (선언/추정/미상). 정밀도 주장 금지. §3-4 |
| 5 | 인계 상한 혼용 | 기존 3분리(`모델` / `optimization/max_vel` / `handoff_max_vel_mps`) 유지. §4-5의 이중 판정이 이를 강제 |
| 6 | 정책 값 조기 동결 | 안정 판정 임계값을 실험 초깃값으로 둔다. §5 |

ADR-0001이 남긴 **재선정 기준** 대조:

| 기준 | 충족 |
|---|---|
| 중립 명명 | ✓ 자체 기체 정의 |
| 데이터 라이선스 명확 | ✓ 서드파티 데이터 0, 라이브러리만 LGPL 링크 |
| 전이 영역 실제 커버 | ✓ 수직 포함. 특이점 없는 표현 |
| 전환·순항 동일 물리 비교 가능 | **△ 부분 충족.** 물리 구현이 둘이 된다. §4-5의 이중 판정으로 보완하나, 동일 공식이던 성질은 잃는다 |
| 용어 중립화 무충돌 | ✓ |

네 번째가 이 제안의 **가장 약한 지점**이다. 승인 시 명시적으로 감수해야 한다.

## 8. 미해결 — 승인 전 답이 필요한 것

### 8-1. Digital DATCOM의 공개 지위
US Air Force 개발이고 널리 쓰이나, 공개 도메인 여부를 이번 조사에서
**확정하지 못했다.** 확정 전까지 계수 추정 방법을 확정할 수 없다.
대안: 교과서 준경험식(공개 문헌).

### 8-2. 추진 스펙이 정해지지 않았다
수직 상승 유지에는 T/W > 1이 필요하다. 현재 0.25.
**목표 T/W, 연소시간, 추진제 질량비를 프로젝트가 선언해야** 형상·관성을
정할 수 있다. 이것이 정해지기 전에는 기체 정의를 쓸 수 없다.

### 8-3. 부스터 분리를 다루는가
분리하면 질량·관성·공력이 불연속으로 바뀐다. 궤적 표현에서 이 불연속을
어떻게 다룰지(구간 분할 여부)가 미정이다. **분리 없는 단일 구성으로 v1을
한정하는 안**을 제안한다.

### 8-4. JSBSim의 결정성
계획기는 결정적이어야 한다(현행 `generate()`는 "no wall clock, no RNG, no
threads" 계약). JSBSim이 고정 스텝에서 이를 만족하는지 **측정 미실시**.

### 8-5. 계산 비용
현행 3DOF 전파는 후보 하나당 밀리초 단위다. 6DOF는 더 비싸다. 후보를 몇 개
굴릴 수 있는지가 유도 법칙 설계를 좌우한다. `jsbsim_probe`가 전파 비용을
이미 측정했으므로 **그 수치를 회수해 시작점으로 삼는다**.

### 8-6. 좌표계 최종 결정
JSBSim은 ECEF 기반이고 계획기는 로컬 ENU다. `jsbsim_probe`가 변환을
해결했으나, 그것을 **계획 경로에 상시로 두는 비용**은 별개다.
