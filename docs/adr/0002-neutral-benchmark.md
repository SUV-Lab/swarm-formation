# ADR-0002: 프로젝트 정의 중립 3DOF 벤치마크 모델

- 상태: **제안 — 리뷰 대기** (2026-08-07). 승인 후 계약 2 v1(§13 선행 정리
  → 1단계 구현)을 시작한다.
- 대체: ADR-0001(기각).

## 결정

계약 2 v1의 구조 검증 모델로 **프로젝트 정의 중립 3DOF 점질량 벤치마크**
를 사용한다.

정확한 정체 선언 — 이것은 "공개 기체 스펙"이 아니다:

| 구성 요소 | 정체 |
|---|---|
| 운동방정식 | **공개** — 교과서 3DOF flight-path 형 (Vdot = (T−D)/m − g·sinγ 등). 구현: `mmp_vehicle_dynamics/point_mass_eom.hpp` |
| 공력·추진 폐합 | **공개 형식** — CD = CD0 + k·CL², 지수 대기. 순항 역동역학(flight_dynamics)과 동일 공식 |
| 파라미터 수치 | **명시적 가정값** — 특정 공개 기체의 데이터가 아니라 이 프로젝트가 선언한 대표값(현행 generic baseline: 질량 1300 kg, 날개 1 m², CD0 0.035, k 0.080, CLmax 1.40, 추력 0–3200 N) |

용도: **알고리즘·연결 구조 검증** — "초기 PVA → 전이 PVA(t) → 다항식 표현
→ 순항 체인 C² 연결"의 증명. **실제 플랫폼 물리 검증에는 사용하지 않으며
그렇게 표기하지도 않는다.**

## 선정 근거 (재선정 조사, 2026-08-07)

- 체인이 소비하는 것은 PVA + C² 연속뿐이다(자세·각속도는 계약이 명시적
  으로 배제). 6DOF 외부 모델이 주는 것(자세·액추에이터 지연·테이블 공력)
  은 현행 계약이 소비하지 않고, 물리 타당성 층은 어떤 공개 예제 모델을
  써도 채워지지 않는다(해당 프로젝트 스스로 교육용 근사라 명시).
- 전환·순항이 **같은 공식·같은 `Parameters`**를 쓰므로 "모델 권위는 한
  곳" 원칙이 구성적으로 성립한다 — 외부 모델을 쓸 때 필요한 이종 물리
  파라미터 추출(ADR-0001 기각 사유 4의 coarse surrogate)이 아예 없다.
- 중립 명명·라이선스 문제가 원천적으로 없다(서드파티 데이터 파일 0).
- 번들 민간 모델 전수 조사 결과: 전이 영역(60–230 m/s·급상승)과 체급을
  동시에 만족하는 중립 모델이 없다.

## 전환 동역학의 구성 (v1)

기존 추종 시뮬레이터를 "재사용"하는 것이 아니다 — 그것은 기존 PolyTraj를
추적하는 컨트롤러다. 재사용하는 것은 **검증된 방정식**이며, 공용
라이브러리로 추출됐다(`point_mass_eom.hpp`: 상태·입력·미분·공력 폐합).
전이 생성기는 별도로 구현한다:

- 상태: 위치, 속력 V, 비행경로각 γ, 진행방향 ψ
- 입력: 추력 T, 양력계수 CL(또는 법선하중), 뱅크 μ
- 독립 RK4 순전파 (추출된 EOM 사용)
- 입력 프로파일 탐색 (계약 §12의 후보 파이프라인)
- 종료 PVA·지속시간 반환 (계약 §5의 TransitionResult)

선언된 표현 한계(모델의 정직한 경계): |γ|는 ~±87°에서 특이(ψ 정의 소실)
— 준수직 발진이 요구되면 모델 확장이 필요하며 가드가 조용히 흡수하게
두지 않는다. 질량 일정. 액추에이터 지연 없음 — 입력 변화율 제한은 탐색
공간의 가정으로 선언한다.

## 속도 상한 의미 분리 (구현 완료)

| 파라미터 | 의미 |
|---|---|
| `dynamics_speed_max` | 물리 모델 유효 상한 |
| `optimization/max_vel` | 계획 선호/비용 상한 (솔버에서 cubic 소프트 비용) |
| `planning/handoff_max_vel_mps` | 순항 인계 계약 상한. 기본 0 = 프레임 상한 추종 |

입구 검증은 min(모델, 인계 계약)으로 판정한다. 위 상한 초과 상태를
거부(INITIAL_MODE_UNSUPPORTED)할지 TRANSITION_REQUIRED로 분류할지는 계약
2 분류기 구현에서 결정한다 — 현행 initceiling 회귀는 구현된 거부 정책을
고정할 뿐, 그 정책의 옳음을 증명하지 않는다.

## 검증 체계의 명명 (v1)

같은 공식·같은 파라미터를 쓰는 전환·순항의 공통 격자 비교는
**consistency test**(인터페이스/구현 일관성 검사)라 부른다 — 물리
교차검증이 아니다(일치는 당연하다). 독립 검증은 별도 문서
`transition_v1_test_design.md`가 정의한다. JSBSim 프로브 하니스는 독립
민감도 비교용으로 유지하되 **합격 판정자가 아니다**.

## 범위 선언 (모든 산출물 필수 표기)

"프로젝트 정의 중립 3DOF 벤치마크 모델(공개 운동방정식 + 명시적 가정
파라미터) 기반 알고리즘·연결 구조 검증이며, 실제 플랫폼 물리 검증이
아니다."
