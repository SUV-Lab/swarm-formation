# 실행 취소 계층 — 남은 작업

초기 플래너 마일스톤(초기 전이 궤적 생성·안정화·중기 C² 연결, leg 정책, FM2 경로
검증, 환경 변경 재평가)은 **닫혔다.** 아래는 그것과 분리된 후속 목록이고, main 머지를
"실행 계층 계약까지 포함"으로 볼 때만 차단 요인이다.

설계와 결정 배경은 `design/exec_cancel_layer.md`.

## 1. 궤적 ID가 플래너 프로세스 수명 동안만 고유하다 — 차단

`TrajContainer::next_traj_id_`는 노드가 살아 있는 동안만 단조다. **플래너만 재시작하면
다시 1부터 시작한다.** 계속 살아 있는 소비자는 이전 인스턴스의 철회 집합을 들고 있으므로,
재시작 직후의 궤적 1이 그 집합에 걸려 거부될 수 있다 — 정상 비행이 시작도 못 한다.

필요한 것: 재시작에 내성 있는 식별자. `planner_instance_id`(기동 시각/UUID) + 노드 내
sequence를 합치거나, 메시지에 두 필드로 나눠 싣는다. **외부 팔로워와 계약을 확정하기
전에** 정해야 한다 — 나중에 넓히면 와이어 변경이 두 번 된다.

소비자 쪽 규칙도 같이 정한다: 인스턴스가 바뀌면 철회 집합을 버릴 것인가, 인스턴스별로
유지할 것인가.

## 2. 시뮬레이터 배선 회귀 — 차단

상태기(`trajectory_abort_state.hpp`)는 시뮬레이터와 회귀가 공유하므로 **잘못된 판단은
잡힌다.** 잡히지 않는 것은 배선이다: `dynamics_sim_node`가 `/planning/execution_control`
구독을 지워도 전 테스트가 통과한다.

필요한 것: 실제 노드를 루프에 넣는 테스트. 주의할 점(워크플로 지적) —
- 두 테스트가 같은 전역 토픽을 TRANSIENT_LOCAL로 쓰면 교차간섭이 난다. 토픽 네임스페이스를
  분리하거나 한 번에 하나만 돌린다
- 두 시뮬레이터 인스턴스는 같은 `/dynamics/sim_state`를 같은 frame으로 낸다. 구독 하나로는
  누가 냈는지 구분할 수 없다

## 3. 외부 팔로워 합의 — 차단

`dynamics_sim_node`가 계약을 구현하지만 플랫폼 실행기가 아니다. 실제 팔로워가
`trajectory_id` 대조와 "철회된 id는 시작하지 않음"을 구현했는지는 이 저장소가 알 수 없다.

## 4. 비차단 보완

- **`fsm_scenarios_test`는 콜백을 직접 호출한다.** 생산 로직 회귀이지 완전한 배선 회귀는
  아니다. 토픽으로 구동하려면 발행자 QoS가 구독자와 호환되어야 한다(TRANSIENT_LOCAL 구독에
  VOLATILE 발행은 전달되지 않는다)
- **`polylineClear`의 "장애물은 어디서도 면제 없음"**은 격리되지 않았다. 시작점 장애물은
  검색 단계에서 이미 거부되므로 그 절만 지우는 변이가 죽지 않는다
- **leg 0 성공 + leg N 실패의 prefix**는 구성 불가다(`fm2fail`은 모든 leg가 실패)
- **ACK 상태 발행** 미구현 (계약에 "가능하면")
- **`setRiskZonesRuntime`은 동일 집합 재발행에도 `zone_policy_generation_`을 올린다.**
  abort는 내용 지문으로 막지만 `environmentRevision()`은 움직인다 — 식별자로서는 무해하나
  일관되지 않는다
