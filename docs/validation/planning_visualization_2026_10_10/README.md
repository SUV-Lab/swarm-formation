# Stage 4 시각화 분리 검증 — 2026-10-10

최종 설치 빌드에서 전체 CTest **41/41**, 공개 메시지 준비 함수 계약 **28/28**, 실제 RViz R2·ABORT·복구 시험을 통과했다. 시각화 연결 유무에 따른 R2 계획 결과도 원본과 같다. 수치 동일성은 이 기록에 포함된 입력과 경로에 대한 검증 결과다.

- `focused/baseline`: 변경 전 설치 정적 라이브러리를 별도로 보관한 뒤 실제 실행해 수집한 기준값. 구현 원본과 라이브러리 SHA는 `source/baseline`, `focused/baseline/installed_archive.sha256`에 있다.
- `focused/connected`: 최종 설치 라이브러리로 같은 입력을 실제 실행한 결과. 11개 토픽의 실시간 40개 메시지, 완전한 표시 상태의 지연 구독 11개, 지운 뒤 지연 구독 11개가 원본과 같다.
- `focused/disconnected`: 같은 설정·환경·갱신 순서를 `PathManager(node, false)`로 실행했다. 실시간/지연 구독 시각화 메시지는 모두 0개였다. ROS 그래프의 발행자 개수를 별도로 측정하지는 않았다. 발행자 생성을 생략하는 경계는 소스에 기록돼 있다.
- 각 `physical_state.txt`: 모든 단계의 환경 revision, 위험도·가시성·그림자 높이 조회, 구형→박스 장애물의 확정 yaw, 다음 RNG 값을 기록했다. 원본·연결·미연결 세 파일이 바이트 단위로 같다.
- `r2`: 실제 Python 지형 로더가 해석한 `r2_ridge_crossing.yaml`을 설치 라이브러리로 계획했다. 연결/미연결 모두 **190개 조각**의 소유한 double 계수·시간, 상태·평가·단계·식별자를 포함한 전체 결과가 원본과 같다. 연결/미연결끼리도 전체 객체가 같다. 기존 float32 궤적 토픽으로 축소한 별도 비교도 수치가 같다.
- `runtime`: 부모 에이전트가 같은 최종 설치 빌드에서 실행한 전체 CTest 41개와 실제 RViz R2·ABORT·복구 로그, JSON, 화면 캡처. chain 71개 변형과 risk 154개도 이 안에 포함된다.
- `source/current`, `integration_manifest.json`: 설치 빌드 전 동결한 변경 파일 12개의 정확한 사본과 해시. `source_after_validation.json`과 설치 전후 SHA 목록으로 검증 중 변경이 없었음을 확인했다.

집중 시각화 입력은 `harness/*/main.cpp`에 명시돼 있다. 위험 구역 2개, DEM 없는 미리보기, 능선/NaN을 포함한 DEM, 5개 위험장 모드, 안전 영역 투명 표시, 전단·파이프라인·구간·궤적·프로파일·히트맵·위험장·장애물, 삭제와 지연 구독을 포함한다. 고정 yaw 시드는 테스트에서만 설정했다. 실행은 컨테이너 `mmp_dev` 내부에서 사용자 계정으로 수행했고, 집중 시험은 ROS domain 88, 외부 R2는 84, CTest는 85, GUI는 82를 사용했다.

`*.cdr`는 실제 받은 ROS 메시지의 직렬화 원본이다. `index.tsv`에 단계·토픽·메시지 타입·파일이 연결돼 있다. `*_canonical.json`은 **`header.stamp`만 0으로 바꾸고** 나머지 필드를 보존한다. 실수는 hex 문자열과 binary64 비트로 함께 보관한다. float32의 유한값은 손실 없이 승격되며 NaN의 부호/페이로드도 Python 변환이 보존하는 비트를 기록한다. DDS의 서로 다른 토픽 간 수신 순서는 비교하지 않고, 같은 단계·토픽 안의 순서를 비교한다. 원본 CDR을 보관하므로 필요하면 ROS 환경에서 다시 해독할 수 있다.

큰 JSON/로그/CDR 일부는 `.gz`로 압축했다. 정적 라이브러리, 실행 바이너리, 빌드 트리는 이 보관본에서 제외했다. `/tmp` 절대 경로가 있는 원시 로그는 실제 실행 기록을 그대로 남긴 것이며 보관본 검수에는 이 디렉터리 내부 파일만 사용한다.

```bash
python3 verify.py
```

위 명령은 ROS와 Docker 없이 표준 Python으로 파일 해시, 동결 소스 사본, 62개 표시 payload의 동등성, 3개 물리 상태 기록, R2의 전체 소유 결과, 28개 계약 검사 및 부모 검증 결과를 검사한다. CDR에서 canonical JSON을 다시 만들려면 ROS 환경에서 `harness/baseline/canonicalize.py <집중시험폴더>`를 실행하면 된다. 압축된 원본은 임시 폴더에 풀어 실행한다. 미연결 결과에는 `--disconnected`를 추가한다.

진행 중 수정한 부분도 보존했다. 첫 격리 컴파일에서 남은 멤버 lambda 캡처/이름 충돌을 정리했고, 소유권 시험의 끝점 예상값을 기존 `T-1e-9` 샘플 규약에 맞췄다. R2 첫 비교는 복사 시 빠진 `compare_runs.py` 때문에 비교 전에 실패했으며, 완료된 연결 계획 결과를 보존하고 원래 보조 파일을 복사한 뒤 비교를 수행했다. 최종 검수에서는 기존 `path_scale=0`·구형 메시 높이 0을 허용하도록 표시값 검사를 정정하고 회귀 검사를 추가했다. 최종 설치 시험은 그 수정 이후 결과다.
