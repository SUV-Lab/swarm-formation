## 남은 결함: 병합 재시도의 설정 우선순위

`SegmentChainPlanner::mergedRetryProfile()`은 원본 phase 설정을 넣은 뒤 양쪽 구간의
유효 제한과 최솟값을 계산한다. 이 과정에서 segment 설정으로 덮였던 낮은 phase
속도 제한이 다시 적용된다. 일반 worker의 phase → segment 우선순위와 다르다.

평탄 지형의 4구간 임무에서 2번 worker 실패를 주입해 실제 병합 경로를 비교했다.
두 경우 모두 `seg2.max_vel=seg3.max_vel=2.0`이다.

| 공통 cruise 제한 | 실제 결과 |
|---|---|
| `2.0` | 병합 성공, 3개 단계 |
| `0.5` | 병합 실패 후 단일 계획 fallback, 1개 단계와 DEGRADED |

개별 구간의 유효 제한이 동일하므로 병합 결과도 같아야 하지만 비교가 실패한다.
기존 시험은 잘못된 phase 값이 segment에 덮이는 경우를 검사하고, 유효하지만 더 낮은
phase 값이 덮이는 경우를 놓쳤다. 병합 제한 합성을 수정하고 이 사례를 회귀 시험에
추가해야 한다. 재현 사본은 저장소 구현을 바꾸지 않고 실제 설치 라이브러리에 연결했다.

관련 관찰로, 한쪽 구간이 `4.0`, 다른 쪽이 기본 `2.0`인 경우에도 다른 쪽에 `2.0`을
명시하거나 생략하는 것만으로 병합 후 최대 속도가 약 `2.010 → 2.212 u/s`로 달라졌다.
암묵적 기본 제한까지 보존하는지는 현재 문서가 명확하지 않아 별도 확정 결함으로 세지
않는다. 같은 설정 합성을 수정할 때 기본 제한의 처리 규칙을 명확히 해야 한다.
