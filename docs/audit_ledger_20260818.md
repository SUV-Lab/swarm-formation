# 감사 원장 — 2026-08-18 고정

**대상 트리** `mmp/6dof-supplier-contract-v1` — 상위 `294f11f9`, 서브모듈 `1690f33a`.
양쪽 작업트리 clean. 이 원장을 쓰는 시점의 HEAD 가 그 두 커밋과 같다.

**이 문서가 하는 일** 읽기 전용 감사가 낸 correctness 14건의 처분을 한 곳에서
정한다. 이후 수정은 여기 적힌 처분을 근거로 하고, 처분을 바꾸려면 이 문서를
고친다.

**이 문서가 하지 않는 일** 감사 보고서를 대체하지 않는다. 원본은 근거와
재현 절차를 담고 있고 이 원장은 그중 **무엇이 여전히 참인지**와 **무엇을 할
것인지**만 담는다.

## 1. 재확인 방법

원장을 고정하기 전에 14건 각각의 인용 `file:line` 을 동결 트리에서 **다시
열었다.** 항목마다 독립 검토자 하나를 붙이고, 인용대로인지(EXACT) · 내용은
맞는데 행이 다른지(MOVED) · 인용한 자리에 다른 것이 있는지(DIFFERENT) ·
아예 없는지(ABSENT) 로 나눠 기록하게 했다.

한계는 그대로 적는다.

- 정적 읽기다. 빌드도 실행도 하지 않았다. 예외는 이미 빌드돼 있던 산출물에
  대한 `nm` 뿐이다.
- 감사가 이미 기각한 impact 서술은 되살리지 않았고 재검증도 하지 않았다.
- 감사 자신이 못 덮은 10개 영역(최적화기 수치, 실기 데이터, RViz 세션,
  다중 기체, 동시성, soak, 보안 등)은 이 원장에서도 그대로 비어 있다.

**결과: 14건 전부 메커니즘 CONFIRMED.** 취소된 항목은 없다. 그러나 인용
앵커와 부수 서술에서 **정정 8건**이 나왔고, **같은 통과에서 함께 고쳐야 할
형제 결함 여러 건**이 새로 드러났다. 아래 §2 와 §3 이 그것이다.

## 3. 재확인이 새로 찾은 것

감사가 보고하지 않았고, **해당 항목을 고칠 때 같은 통과에서 처리해야** 하는
것들이다. 따로 번호를 매기지 않고 원 항목에 붙인다.

### V-2 에 붙는 것

- **두 번째 낡은 경로.** 감사는 `:628`(`start_pt_ = current_pos_`)만 지목했다.
  `have_local_traj_` 가 참인 채로 채택이 건너뛰어지면 `:615` 에서
  `start_pt_ = theoretical_pos` — **이전 궤적의 표본점**이 쓰인다. 저장소 자신의
  `open_questions.md:14` 가 말하는 "미션 B 가 미션 A 의 궤적점에서 계획한다"가
  바로 이 경로다.
- **저장소 계약이 패널 전용 처방을 이미 강등해 뒀다.** `initial_speed_contract.md:127`
  — *"the contract must not depend on publisher hygiene for its central guarantee."*
  감사는 "패널에서 Run 마다 `mission_id` 를 만든다"를 대등한 선택지로 적었으나,
  트리의 계약은 그것을 **부차적 경화**로 규정한다.

### V-3 에 붙는 것

- **등록 시 걸리는 함정.** `risk_scenarios_test.cpp:407-409` 의 yaml 기본 경로가
  **CWD 상대**(`src/mmp_terrain/data/risk_scenarios/synthetic_flat.yaml`)다.
  ctest 등록은 `WORKING_DIRECTORY` 를 빌드 디렉터리로 잡으므로 그대로 등록하면
  적재 실패로 exit 2 가 난다. 등록 작업의 첫 장애물이다.
- **미등록 바이너리 모집단이 둘보다 크다.** `path_planner` 가
  `sdf_dynamic_test`·`sdf_tool`·`fm2_gpu_test` 를 더 만든다. "등록 0" 판정은
  불변이나 편입 범위를 정할 때 셋을 알고 있어야 한다.
- **비용 관점이 뒤집힌다.** `terrain_risk_mask_test` 가 이미 최적화기 본문을
  링크하고 있으므로, 4569행 최적화기에 **실행되는** 커버리지를 주는 비용은
  객체 하나 생성 수준이다.

### V-4 에 붙는 것

- **진짜로 검사되지 않는 분기는 감사가 지목한 쪽이 아니다.** fm2 가 geodesic 을
  버리거나 `fm2_valid_` 가 거짓이면 A\* 분기로 내려가는데, 거기 성공 조건은
  `path.size() > 1`(`dyn_a_star.cpp:763`)뿐이고 `:841` 전에 어떤 폴리라인 검사도
  없다. **그 경로는 장애물 절반도 지형 절반도 못 받는다.**
- **작성자의 기대가 코드에 적혀 있고, 조기 반환이 정확히 그것을 무효화한다.**
  `dyn_a_star.cpp:715-718` — *"Terrain clearance is judged on the FINAL path,
  after the simplification and the terrain-lift sweep have had their chance to
  fix it — see polylineObstacleClear and the whole-path check before this
  function returns."* 지형 검사를 뒤로 미룬 것이 의도이고, `size <= 2` 반환이
  그 "뒤"를 없앤다. 의도된 절충이 아니라는 근거가 주석 자체다.
- `path_manager.cpp:1927` 은 인용문이 붙인 수치를 담고 있지 않다. 실제로는
  `0.30` 밴드 대 `~0.21` 평형이지 `0.50` 여유가 아니다. "물러선다"는 질적
  요지는 지지되나 수치 짝은 아니다.
- `chain_experiment_test.cpp:2551` 은 "(measured, 68 variants)" 인데 현재 트리의
  스윕은 **69** 다. 그 주석이 근거로 대는 측정이 한 변형 작은 스윕에서 나왔다.

### V-5 에 붙는 것

- **바닥 쪽에 같은 결함이 있고 제목이 그것을 말하지 않는다.** `:755` 의
  `s.speed_mps < dyn.model_activation_speed_mps` 도 맨 `<` 다(`:392` 는 `-1e-9`).
  정확히 활성화 속도를 진술한 시작도 같은 방식으로 거부된다. **수정은 두
  피연산자를 모두 덮어야 한다.**
- **같은 두 한계에 트리 안 허용오차가 셋이다.** 공용 교리

  `1e-9` · `:754-755` 의 없음. 수정은 리터럴을 하나 더 늘리지 말고 **공용
  헬퍼를 부르는 쪽**이어야 한다.

#### 감사 결과 (2026-08-19) — `u²` 를 회귀 값으로 고정하지 않는다

`u²` 가 요구 계약이라는 근거를 찾지 못했다. 지수가 무해한 자유 변수라는 근거도
없다. 값을 고정하지 않고 미결로 둔다.

**먼저 위 서술 한 줄을 정정한다.** "`risk_int` 가 20.765 → 21.968 로 움직인다"
는 하니스가 **단언하지 않는** 행이다. 원문이 그렇게 적혀 있다 —
`[info] sub-production alpha=0.1: DETOUR not asserted`
(`log/test_2026-08-17_18-19-18/path_manager/stdout.log:438`). 단언은 `alpha ≥ 10`
에서만 걸린다(`risk_scenarios_test.cpp:378-388`). 변이의 진짜 효과는 아래 §4 에
있고, 방향이 반대다.

##### 1. `u` 의 정의와 범위

- `u = 1 - q`, `q = sqrt((dx²+dy²)/reach² + dz²/rv²)` — 정규화된 **타원체 반경**.
  `u` 는 구역 안쪽 **깊이**다. 중심 1, 테두리 0. (`dyn_a_star.h:517-549`)
- 범위 `(0, 1]`. 클램프는 없고 구조가 보장한다 — `q` 는 제곱합의 제곱근이라 `≥ 0`,
  바로 위 `if (q >= 1.0) continue;` 가 `q < 1` 을 보장한다(`dyn_a_star.h:536`).
- 무차원. 가시성은 별도 곱이지 `u` 의 일부가 아니다(`dyn_a_star.h:538-544`).
- 실제로 `rv` 는 존별로 쓰이지 않는다. `reach * risk_vertical_ratio_`(기본 0.35)로
  채워져 편평 타원체가 된다(`path_manager.cpp:1315-1317`).

**따라서 제곱은 증폭이 아니라 감쇠다.** `u ∈ (0,1]` 이므로 `u² ≤ u`, 등호는 중심뿐.
변이 `u²→u` 는 테두리 안쪽 전 구간에서 페널티를 **키운다**. 중심 값은 지수와 무관하다.

##### 2. 제곱이 의도된 비용 형상인가

사본 다섯이 전부 `u * u` 다. 지수에 이견은 없다.

| 위치 | 식 |
|---|---|
| `dyn_a_star.h:544` | `tz.peak * u * u * visibility * endpointTaper(zi, pos)` |
| `poly_traj_optimizer.cpp:3995` | `const double base_m = tz.peak * u * u;` |
| `path_manager.cpp:1668` | `moat = tz.peak * u * u * visibility;` |

##### 4. `u` 와 `u²` 가 경로 선택에 만드는 차이 — 재측정

`log/test_2026-08-17_18-17-28`(기준) 대 `log/test_2026-08-17_18-19-18`(변이).
두 실행 사이 다른 변경은 없다. 양쪽 합 **572행**이 다르다.

단언이 걸리는 DETOUR 7건 (`alpha=10`; 한계 `risk_int < 5%·direct`, `max_depth < 5 m`):

| 시나리오 | `risk_int` u²→u | `max_depth` u²→u | 기준의 여유 소진 |
|---|---|---|---|
| S1_single_zone | 0.000 → 0.000 | 0.0 → 0.0 | 0% |
| S2_two_overlapping | 0.000 → 0.000 | 0.0 → 0.0 | 0% |
| S5_sdf2_mimic | 0.002 → 0.000 | 0.8 → 0.0 | 16% |
| S10_zone_rows | 0.022 → 0.000 | 1.3 → 0.0 | 26% |
| S9_wall_blocking | 0.033 → 0.000 | 1.5 → 0.0 | 30% |
| S14_vertical_detour | 0.094 → 0.000 | 2.5 → 0.0 | 50% |
| S13_asymmetric_peaks | 0.052 → 0.000 | 3.3 → 0.0 | **66%** |

**통과한 이유는 경로가 안 바뀌어서가 아니다.** 경로는 실제로 바뀐다 — `alpha=10`

원리적으로 잡히지 않는다. 모든 단언이 한계에서 **멀어졌다**.

반대 방향을 막는 것은 길이 예산뿐이고, 그쪽은 이미 빡빡하다:

|---|---|---|
| S4_goal_in_zone | APPROACH (1.5×) | **94% → 93%** |
| S12_giant_middle_zone | TRANSIT (2.0×) | 73% → 80% |
| S3_encircling_band | TRANSIT (2.0×) | 62% → 71% |

덧붙여 **하니스 지표는 시험 대상 코드를 호출하지 않는다.** `risk_int` 는
`pathRisk`(`risk_scenarios_test.cpp:131-148`, `:318`)가 내는 값이고, 그 함수는
**구형** 거리에 자기 `u*u` 를 다시 박아 쓴다(생산은 타원체다). 돌아온 경로를
재채점할 뿐이라 플래너의 식 변화 자체는 감지하지 못한다.

지수를 `1e-6` 로 못박은 단언은 딱 하나 있고, 변이된 사본이 아니다 —
`peak=0.8, q=0.5 → 0.2`(`terrain_risk_mask_test.cpp:108,127`), 즉 사본 4.

##### 5. 못박을 것은 식이 아니라 성질

아래는 `u` 와 `u²` 양쪽에서(사실상 `u^k, k>0` 전부에서) 성립한다. 정책 결정이
어느 쪽으로 나든 시험이 살아남는다.

| 성질 | 근거 | 지수 무관 이유 |
|---|---|---|
| `q ≥ 1` → 정확히 0 | `dyn_a_star.h:536`, `path_manager.cpp:2309`, `poly_traj_optimizer.cpp:3993` | 가드가 지수 앞에 있다 (1건 이미 고정: `terrain_risk_mask_test.cpp:130-131`) |
| 중심 값 = `peak · visibility` | `dyn_a_star.h:537,543-544` | `q=0 → u=1 → u^k=1` |
| 중심→밖 비증가 | 위와 동일 | `q` 증가 → `u` 감소 → `u^k` 감소 |
| `visibility=0` 또는 `peak=0` → 0 | `dyn_a_star.h:540-541`, `path_manager.cpp:2311` | 곱 구조 |
| 존별 값 ≤ `1-1e-3`, 합성 ∈ `[0,1)` | `dyn_a_star.h:545-547` | 캡 + 생존확률 곱 |
| 존을 더해도 위험 비감소 | `dyn_a_star.h:546-547` | 곱 구조 |

**이번 변이를 실제로 잡는 것은 따로 있다 — 계층 간 필드 동일성.**
같은 점에서 전단 `getRiskNorm` == `riskZoneValue` 합성 == 후단 `base_m` 이어야
한다. 코드가 이미 두 곳에서 불변식으로 선언한다(`path_manager.cpp:1643-1647`,
`poly_traj_optimizer.cpp:3876-3881`). 변이는 사본 다섯 중 하나만 옮겨 이것을
조용히 깼다. 지수와 무관하게 검사된다.

작성 비용을 정직하게 적는다 — `getRiskNorm` 은 private 이라(`dyn_a_star.h:375`)
읽기 전용 조회 훅이 필요하고, 사본들이 정당하게 다른 세 항(taper, `rv` 삼중
재계산, 후단의 넓은 지지)을 픽스처가 먼저 정리해야 한다.

**하지 않을 것:** 지수 고정, 하니스 731행 값 고정. 후자는 위에서 경고한 사본
하나를 더 만들 뿐이다.

### PA-7 · **CLOSED** — `peak` 이 검증 없이 들어왔다

`(0, 1]` 은 이미 두 곳이 MUST 로 선언한 계약이다(`path_manager.h:43`,
`risk_zones.yaml`). 정책 선택이 아니라 기존 계약 위반이다.

**유입 두 곳 모두 뚫려 있었다.**

| 유입 | 이전 | 지금 |
|---|---|---|
| yaml 파라미터 (`path_manager.cpp:332`) | 검증 전무 — 0·음수·>1·NaN·Inf 전부 통과 | 전량 검사, 하나라도 불량이면 **전체 거부** |
| 실행 중 메시지 (`replan_fsm.cpp`) | 유한성·`>0` 만 봄. 불량 존을 **버리고 나머지 채택** | `>1` 포함 전량 검사, 불량이면 **갱신 자체를 거부**, 기존 집합 유지 |
| `PathManager::setRiskZonesRuntime` | 검증 없음 | 같은 검사, `bool` 반환 |

**버리기(drop)는 위험하다.** 임무가 선언한 위험 구역이 조용히 필드에서 사라지고
플래너는 그리로 직진한다. 집합째 거부하면 필드가 눈에 보이게 그대로 남고 ERROR
가 남는다.

`>1` 도 거부한다. 이전 근거는 "캡에 saturate 된다"였는데, 그게 바로 피해다 —
포화된 구역은 부피 대부분에서 gradient 가 없어 회피 성형이 사라지고 배리어만
남는다.

#### 이 변경을 "fail-closed" 라고 부르지 않는다

**용어 정정 (사용자 지시).** 초기 입력이 불량일 때 존 0개로 계획을 계속한다면
시스템 전체로는 fail-closed 가 아니다. 넣은 것은 정확히 다음 셋이다.

1. **원자적 거부** — 입력 집합을 부분 채택하지 않는다. 한 건이라도 불량이면 그
   집합은 통째로 효력이 없다.
2. **실행 중 갱신은 기존 정상 집합 유지** — 거부된 갱신은 활성 집합을 건드리지
   않는다.
3. **초기 불량 설정에서 계획 지속 여부는 미결정** — 아래 후속.

노드 중단이나 계획 거부는 넣지 않았다. V-8 에서 정한 대로 임의로 중단 동작을

### PA-5 · REGRESSION-NET GAP (높은 우선순위)

**FM2 의 raw/final 단계 분리가 어디에도 고정돼 있지 않다.**

V-4 를 닫지 못해서가 아니다. V-4 는 닫힌다. 이것은 **새로운 회귀망 공백**이고,
2026-08-18 병합에서 실제로 회귀를 통과시켰기 때문에 일반적인 개선보다 우선순위가
높다.

#### 고정되지 않은 계약

```
raw FM2  ->  장애물만 검사  ->  지형 보정  ->  최종 전체 검사
```

**단계별 책임**이 계약이다. 원 geodesic 은 씨앗이라 지형으로 거부하면 안 되고
(뒤의 지형-리프트 스윕이 그 일을 한다), 장애물은 어떤 리프트로도 못 빠져나오므로
그 자리에서 거부해야 한다. 지형은 보정이 끝난 최종 경로에서 본다.

기존 회귀는 **구성 요소를 각각** 검사한다 — `polylineClear` 를 순수 술어로,
최종 게이트를 호출부로, 실미션을 통째로. **순서와 책임 분담은 아무도 보지
않는다.** 그래서 병합이 raw 단계의 기준을 바꿔도 86개 시험·70개 변형·실미션이
전부 통과했다.

#### 필요한 사례

| | |
|---|---|
| 원경로 | 지형 여유는 부족하되 **장애물은 없음** |
| 지형 보정 후 | 최종 경로가 지형·장애물 검사를 **모두 통과** |
| 구성 | A\* 풀이 없는 FM2 경로(출하 설정과 동일)에서도 **계획 성공** |
| 변이 1 | 원경로 검사를 `polylineClear()` 로 되돌리면 **반드시 실패** |
| 변이 2 | 원경로에 실제 장애물이 있으면 **즉시 거부** |

변이 1 이 이 항목의 핵심이다 — 그것이 이번 병합 회귀를 잡았을 검사다.

#### 원인으로 기록할 것

**머지 충돌에서 "더 강해 보이는" 검사를 고르면 단계별 책임이 깨질 수 있다.**

이번에 정확히 그랬다. `mmp_dev` 쪽은 지형까지 보므로 더 엄격해 보였고 그래서
취했는데, 그 엄격함이 **틀린 단계**에 놓여 있었다. 더 강한 검사가 더 나은
검사가 아니다 — 어느 단계가 무엇에 책임지는지가 먼저다.

부가 정황: `mmp_dev` 는 08-13 에 갈라졌고 분리 수정은 08-14 에 들어왔다.
한쪽에만 있는 나중 수정을 hunk 단위로 판단하면 되돌리기 쉽다. 충돌 해결에서
양쪽 hunk 의 **날짜와 의도**를 먼저 봐야 한다.
