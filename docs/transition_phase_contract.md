# TransitionPhase 설계 계약 (계약 2, 문서만 — 코드 없음)

- 상태: 인터페이스 계약 확정, 구현 보류 (2026-08-06 설계 리뷰 수렴)
- 보류 사유: 전환 영역 한계 수치가 기체 스펙에서 확정되기 전에 골격 코드를
  만들면 잘못된 인터페이스가 굳는다. 수치 도착 전까지 이 문서가 계약을
  한 곳에서 정의한다.
- 전제: 계약 1은 구현 완료 — 명시 초기 상태의 영역 검증
  (`INITIAL_MODE_UNSUPPORTED`), phase 모드 direct fallback의 비행 적합성
  게이트 (`DIRECT_FALLBACK_UNSAFE`). `planning_result.h`,
  `PathManager::stateEnvelopeProblem()`, 회귀 변형 initfail / initok /
  synthclamp / unsafedirect / departop 참조.

## 1. 역할 정의 — 두 "출발"의 의미 분리

- TransitionPhase: 순항 모델 **밖**의 초기 상태(영역 밖 속력·상승각)를
  유효 영역 **안**으로 데려오는 구간. 전용 동역학 모델·한계 집합으로 계획.
- 기존 departure(체인 1구간): 유효 영역 **안**의 상태를 전역 경로에
  정렬하는 구간. 순항 모델 그대로.
- 두 구간은 겹치지 않는다. TransitionPhase의 종료 상태가 곧 departure가
  시작할 수 있는 상태다.
- 근거 결함: 상승각 32°(모델 콘 ±30°) 초기 벡터가 계약 1 이전에는 직행
  강등으로 흘러갔고, 그 이전에는 548.7 u 벌레 궤적이 SUCCESS로 통과했다
  (logs/runtime/replan_fsm_drone_0_20260806_054645.log,
  피크 추력 299.2%는 054808 · 064053 로그).

## 2. 파이프라인 (수렴 구조)

```
[실제 초기 PVA — 순항 모델 밖 허용]
   ↓                      (전역 FM 경로는 이미 존재)
전이 생성기 — 전용 모델·한계로 시간 궤적 PVA(t) 생성
   목표 = 전역 경로 위 진입 후보 (기존 선별 규칙 재사용)
   ↓
다항 어댑터 — Hermite/MINCO 구간 구성 (§4 내부 검사 필수)
   ↓
(선택) 참조 추종 L-BFGS — §5 계약
   ↓
공용 실행 적합성 검사 — 지형·존·영역, 접합 jerk 감사 (§6)
   ↓ 종료 PVA = prescribed head
SegmentChainPlanner — 경로 슬라이스 [entry..goal] 로 재계획 (§3)
```

## 3. 접속 계약 — 경로 슬라이스와 prescribed head

- 공간 정합 방식은 "경로 우선"으로 확정: 전역 FM 경로를 먼저 만들고, 전이
  생성기가 그 경로 위의 진입 후보를 목표로 삼는다. 경로는 전역 1회
  결정(구간별 재탐색이 다른 위상을 골라 실패한 r3 교훈)이라는 기존 원칙
  그대로다. 전이 끝점을 경로에 투영하거나 잔여 경로를 재생성하는 방식은
  채택하지 않는다.
- 체인 입력은 전역 경로 전체가 아니라 **진입 후보부터 잘린 슬라이스**다:

```
전역 경로  [start ... entry ... goal]
                     ↑ TransitionPhase 종료
체인 입력 = [entry ... goal]
prescribed head = TransitionPhase 종료 PVA
```

- 인터페이스에 `route_start_index`(또는 진입점 arc 길이)가 명시돼야 한다.
  슬라이스 없이 전체 경로를 넘기면 체인이 원래 시작점부터 departure를
  다시 만들어 전이 구간과 중복된다.
- 중기 궤적은 "이미 있는 것에 붙이는" 것이 아니다. 전이 종료 PVA를 head로
  받아 그 시점에 다시 푼다. 순서가 전이 → 체인이므로 재계획 요구는
  구조적으로 충족된다.

## 4. 다항 어댑터 — 구간 내부 검사

- Hermite 변환은 근사다. 샘플 점에서의 일치가 샘플 **사이**의 제약 준수를
  보장하지 않는다 (나선 하강의 오차 1e-18은 해석 샘플이 촘촘했던 결과이지
  면제 근거가 아니다).
- 고정 간격 샘플링만으로 검사를 끝내면 안 된다. 둘 중 하나 이상:
  - 다항 극값 검사: 속력²·상승률 등 검사 대상을 다항으로 미분해 구간 내
    극값 위치를 직접 구해 판정.
  - 적응형 세분화: 위반 여유가 얇은 구간을 재귀 분할해 수렴할 때까지 검사.
- 검사 대상: 전환 한계 집합(§7) 전 항목 + 지형·존.

## 5. 참조 추종 최적화 계약 (선택 단계)

- 시작·종료 PVA: hard (경계 조건, 이동 금지).
- 전이 원형(생성기의 PVA(t)): reference 비용 — L-BFGS가 전이 알고리즘의
  의도를 지우지 못하게 한다.
- 전환 한계 집합: gate — 순항 한계가 아니라 전환 전용 수치로 판정.
- 시간 배분: 제한적 조정만 허용 (원형의 시간 구조 보존).

## 6. 접합 연속성 — jerk는 감사, 보장이 아님

- 체인 접합은 C² (P/V/A 일치 ~1e-13). C³은 보장하지 않는다.
- 따라서 전이→체인 접합의 jerk는 "연속 보장"이 아니라 **점프 크기 감사 +
  상한 판정**으로 정의한다: 좌극한/우극한 jerk 차의 노름이 상한(전환 한계
  집합의 항목)을 넘으면 부적합.

## 7. 미확정 — 기체 스펙에서 올 수치 (자리 이름만 정의)

- 전환 허용 속력 구간 (순항 120–230 m/s 밖 어디까지)
- 전환 허용 상승각 (순항 콘 ±30° 밖 어디까지)
- 전환 하중·추력 가정
- 접합 jerk 점프 상한
- 전이 완료 판정 임계 (속력 수렴 폭, 접선 정렬 각, 유지 시간)

이 수치들이 오기 전에는 생성기·어댑터·게이트 어느 것도 구현하지 않는다.

## 8. 실패 의미론

- 전이 생성 실패 / 어댑터 내부 검사 실패 / 접합 감사 실패 → 미션 FAILED
  (전환 영역에서 direct fallback은 없다 — 순항 플래너는 그 영역을 못 푼다).
- 전이 성공 + 체인 강등 → 체인의 기존 DEGRADED 의미론 그대로.
- 계약 1의 `INITIAL_MODE_UNSUPPORTED`는 TransitionPhase가 켜지면 "전환
  한계까지도 밖"인 입력에만 남는다.
